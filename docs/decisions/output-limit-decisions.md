# 失控止损裁决（2026-09-15 起）

- 定位：M6.5 冒烟中模型生成工具参数时转义错位、退化输出直到写满模型输出上限，单轮耗时十余分钟；为无人值守与后台运行设止损
- 裁决：项目负责人；基线 7818dee
- 方式：拆为三件逐件裁决

## 事实

- 单轮输出上限目前取模型定义值：pi-ai 请求参数为 `options.maxTokens ?? model.maxTokens`，Kimi For Coding 的模型定义为 32,768；Pigeon 未另设。
- 上游 agent-loop 在 stopReason 为 length 时把该消息里的全部工具调用判为未执行，回给模型固定文案"参数可能被截断，请重发完整参数"，不会执行残缺参数；该文案与判定在上游，不可改。被截断的调用不经过 beforeToolCall 与 afterToolCall 钩子。
- 上游 agent-loop 以 `{ ...config, apiKey, signal }` 调用 streamFn；Pigeon 持有 streamFn，可在装配层包装并传入 maxTokens。
- 生成中途 abort 时该轮 stopReason 为 aborted，agent-loop 随即结束整个 Run。
- 两次 Eval 保留的会话账本共 1,396 轮：输出 token 中位 99、p99 1,478，正常轮次最大 3,406；超过 4,000 的只有 2 轮，均为失控且恰为 32,768，出现在同一任务的同一行代码。输出速率约每秒 46 token，写满 32,768 约 11.8 分钟。
- Eval 结果行的过程指标已记录撞输出上限轮数（`process.outputLimitTurns`）。

## 第 1 件：单轮输出上限

| 选项 | 失控一次最长耗时（约） | 相对正常最大轮次的余量 | 评估 |
|---|---|---|---|
| 维持 32,768 | 11.8 分钟 | 很大 | 现状 |
| 8,192，可配 | 3 分钟 | 约 2.4 倍 | 生成大段内容时有误截断可能 |
| 16,384，可配 | 6 分钟 | 约 4.8 倍 | 基本不误伤，止损减半 |
| 4,096，可配 | 1.5 分钟 | 约 1.2 倍 | 贴近正常轮次，误截断概率明显 |

裁决：16,384，可配。项目负责人明确要求正常输出不得被截断，取余量更大的一档；上限值写进启动快照以便事后可证。

## 第 2 件：截断后的引导

| 选项 | 做法 | 评估 |
|---|---|---|
| 不做 | 依赖上游固定文案与熔断 | 模型可能原样重发同一大段内容 |
| system prompt 指引 | 写明被截断时拆成几次较小的调用重发、不原样重发，单次编辑只改需要改的一段 | 静态文本、对 prompt cache 友好，改动数行；依赖模型遵守 |
| 截断后动态插入提示消息 | 检测到 length 后在下一轮上下文插入提示 | 只能以 user 角色插入，与 042 否决的伪装用户发言冲突，并改变 042 / 044 的 transformContext 只观察口径 |
| 截断即中止 Run | 一次截断视为失败 | 16k 上限下被截断的多为可拆小救回的长输出，直接判失败浪费任务 |

裁决：system prompt 指引，两种编辑模式都加。

## 第 3 件：流式重复检测与提前掐断

| 选项 | 做法 | 评估 |
|---|---|---|
| 本轮不做 | 依赖第 1、2 件、熔断与墙钟，以 `outputLimitTurns` 观察频率 | 零改动；失控一次最长约 6 分钟 |
| 检测到退化即 abort | 包装层监听 toolcall_delta，启发式判断 | 止损快，但整个 Run 失败，误报即杀掉正常任务 |
| 提前结束本轮并按截断处理 | 结束流并合成 length 停止原因 | 任务可继续，但账本中的停止原因不再是 provider 真实返回值，改写证据；误报问题同样存在 |
| 只观测不干预 | 疑似退化时记观察记录 | 积累启发式判据的数据，本身不止损，需加法式新增记录族 |

裁决：本轮不做。理由：失控样本只有 2 个且集中在同一位置，据此调启发式会过拟合；误报代价（杀掉正常任务或改写证据）高于失控多耗的数分钟；第 1、2 件已把最长耗时减半并提供拆小引导；撞输出上限轮数已在 Eval 结果行中记录，频率明显上升时再议。

## 施工口径（不裁决）

- 包装 streamFn 传入 maxTokens；模型定义值更小时取更小者；开推理时与推理预算共用额度的实际行为需测试确认。
- 上限值进入注入快照 model 段，加法式升版；cli、tui、headless、`pigeon run`、`pigeon eval` 可配，worker 继承父运行面的值。
- 用测试确认被截断的工具调用计入上游拦截熔断（同一工具连续 3 次中止 Run）。
