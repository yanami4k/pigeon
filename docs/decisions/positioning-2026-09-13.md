# 项目定位裁决（2026-09-13，索引 039）

- 定位：路线图 §1 的项目定位改写，以及由此派生的账本去向与权限功能冻结口径
- 起因：盘并行编排与 Trace 价值时，"治理闭环是差异化"这一叙事被重新审视
- 裁决：项目负责人；结论落 ROADMAP §1 与 decisions.md 039（含同日修订行）

## 问题

路线图 v0.5 的 §1 以"治理闭环"作为项目差异化：人工审批、六档放权、证据链、OutcomeUnknown 不盲重放、单一权威源、学习产物默认暂存。需要回答：这套治理对 coding agent harness 的使用者而言是不是卖点。

## 分析

- 对终端前的开发者，权限与审批是摩擦不是卖点。行业现状：批发放行与跳过审批的开关是最常用选项；主流 coding agent 的竞争在模型效果、上下文工程与速度；allow / deny 清单是及格线不是差异化。以"有审批和证据链"作自我介绍，会被归为合规工具。
- 治理本身不卖，治理换来的东西卖。两样：
  - 无人值守：敢把 worker 派出去自行运行，醒来能对账，崩了不盲重放。主流产品对 hooks、沙箱、自动模式的投入同样是为了让人少盯着，对外叙事是"自主"而非"权限"。
  - 自我改进不翻车：M7 到 M9 的提炼、Eval、激活闭环，对外一句话是"它会从自己的历史里学"；默认暂存与人工审批是保险，不是卖点。
- Trace 的两个价值：对使用者是信任与恢复，对开发者是迭代。前者的严格性（事实不是摘要、完整不是抽样、017 宁标未知不贴错标签）正是后者数据质量的保证。
- 风险：M2 到 M4 全在打地基；若后续继续把时间投入治理管道而并行与学习迟迟不出场，项目最终只是带审批的 pi-agent-core 包装。

## 裁决

- 不改架构，改叙事与顺序：§1 定位改写为"卖点是无人值守的并行执行与从运行历史学习，治理闭环是这两样能力成立的原因"；§3 不可妥协约束与 §4 架构一字不改。
- 演示与验收以并行编排（§M5.5）与学习闭环（§M7 到 §M9）为主角；治理只在"崩溃或中断之后能对账能恢复"与"学到东西之后能审能回滚"两个场景露面。
- 里程碑排期以尽早让两个主角出场为准：M5.5 紧接 M5，M7 尽早。排期具体变更随 040 一起改 §5。

## 同日修订：账本去向与权限功能冻结

- 权限部分是否过重：用户可见层（四键、yolo、[a]/[d]、/grants save）与主流产品持平，缺命令级模式规则与操作系统沙箱；不可见层（意图哈希、回执、拒绝理由、放权四族、升格一次、熔断、崩溃对账三选一，约 900 行在 Adapter）比同行重。其中崩溃对账与升格留痕属于超前：前者真正派上用场是 exec 工具与无人值守 worker，后者是审计叙事。
- 账本的价值：账本是整本 Event Log 十三族，Receipt 只是治理族一条。消费者有恢复、解释（trace / replay）、agent 翻旧账（037 / 038）、并行编排（父子链接）、学习与评测（M7 / M9）。权限只是第一个消费者。
- 裁决：账本原样保留不拆；后续消费者优先学习闭环、Session Search 与并行编排；权限、审批、放权、固化留痕类功能非必要不新增，只在两个主角明确需要时补（如 exec 工具到来时补命令级模式规则与沙箱）。

## 补充：账本与学习闭环的关系（2026-09-14）

"重账本是不是天生适合学习"的结论：适合在"数据可信"，但"从原料到经验"还缺三样，是 M6.5 到 M7 的正题，不是账本自动带来的。

账本给学习提供的四样原料，普通 agent 的对话记录只有第二样的一半：

| 原料 | 账本里的来源 | 学习怎么用 |
|---|---|---|
| 干净的结果标签 | 失败四分类宁标未知不贴错标签；确定性验证器的回执 | 蒸馏最怕毒标签，"模型说成功了"不算数，回执说才算 |
| 完整的动作序列 | tool.proposed 到 settled，参数、返回、耗时、错误分类 | 成功路径与失败路径差在哪一步，能逐步对比 |
| 决策依据 | 拒绝理由、审批出处、放权记录、thinking 正文 | 负样本有解释，不只是"错了" |
| 复现条件 | run.started 冻结的模型、策略、Memory 与 Skill 版本，llm.request 指纹，usage | 能回答"同样任务换一版 Skill 结果变了吗"，M9 三向对照的前提 |

还缺的三样：任务边界（账本按 Session 与 Run 记，学习要按"一次任务"切，Episode 从哪条到哪条没有定义）；对比对（对比式蒸馏要同一任务的成功与失败两条路径，单条只能总结不能对比，要靠 lane 分支或 Eval 重复运行制造）；任务级成败（回执只说"这次写入生效了"，不说"任务做对了"，要验证器，coding 是测试，其他场景是 M6.5 定的确定性验证器，没有验证器的只能人标）。
