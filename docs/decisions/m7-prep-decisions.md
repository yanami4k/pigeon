# M7 前置裁决（2026-09-16 起）

- 定位：M7 整棵会话树的对比式经验提炼开工前的十二件前置
- 裁决：项目负责人；基线 9f440fe
- 依据：ROADMAP §M7、§3.3、§3.5、§3.7、§3.8、§6；decisions.md 006、013、039、040、042、043、057、058、060、064、065、066；docs/decisions/positioning-2026-09-13.md（学习闭环缺的三样：任务边界、对比对、任务级成败）

## 事实

- Pigeon 持久化数据中没有会话树：entry 记录只有 `(runId, runSeq)` 与角色，无父指针（src/state/event-log.ts 的 EntryRecordSchema）；一个会话文件是多个 Run 线性追加，resume 续写时模型上下文从零重建；未实现 lane、回退或分叉；worker 通过会话头的 parentSessionId / parentRunId 与父会话形成委派关系，不是对话分叉；带"父"语义的字段只有这两处与候选的取代关系。
- pi-agent-core 0.84.4 的会话层有真实实现：`Session` 提供按分支查询、追加消息、建 lane 与移动 lane；`JsonlSessionRepo` 的根目录可指定、会话头带应用自有元数据；`buildSessionContext` 可把一条分支还原为 Agent 消息；`createSessionBackendConformance` 为现成契约测试；`Agent` 的初始状态可传入历史消息。
- 上游 `AgentHarness`（把 Agent 运行与会话树接起来的一层）为桩实现，prompt、navigateTree、resume、compact 等方法均抛未实现；上游没有任何组件把运行写入会话树，Pigeon 也未引用上游会话模块。
- 路线图引用的"Pi Session Format"文档属于 pi-coding-agent（v3 格式），本地 core 0.84.4 的 JSONL 编解码为 v4；本地未安装 pi-coding-agent。
- 现成的同任务多次尝试只有 Eval：每次运行一个会话一个 Run，按任务编号、条件与次序对齐，会话中有带任务编号的 eval.verified。
- 一级成败证据只有 eval.verified；run_command 回执有退出码与文件变化但无"验证命令"标记；人工审批决定针对单次调用，无任务级确认。
- 外部先例：做成败成对比较的 ExpeL、AutoGuide、ETO，对比对均来自同一任务的独立多次尝试，标签来自环境或测试，无一依赖会话内分叉；AutoGuide 定位两条轨迹的首个分歧步。W2S / Skill-IR、AWM、Voyager、Reflexion、ReasoningBank、SWE-Exp 不做成败配对或只学成功。
- 真实会话统计（98 个会话）：一次完整尝试正文中位约 19,800 字符、p90 约 51,300、最大约 85,100；正文 89% 为工具结果。

## 裁决

| # | 事项 | 选项 | 裁决 |
|---|---|---|---|
| 1 | 对比素材来源 | 先自建会话树 / 只用同任务独立尝试 / 两者都做 | 两者都做，先同任务比对、后分叉，均在 M7 内完成；分叉以上游 Session 存储与上下文还原为基础，由 Pigeon 补写穿与分叉续跑接线；账本为唯一权威，会话树为派生结构 |
| 2 | 同任务认定 | 显式任务标识 / 任务原文哈希 / 模型判断 | 显式标识：Eval 用任务编号；并行派发同一任务时生成共享任务标识，加法式写入派出记录；普通会话不自动归组，交给分叉 |
| 3 | Episode 边界 | 按来源定边界 / 按整个会话 / 按上下文断点切段 | 同任务比对取尝试会话的首个 Run；分叉取分叉点到叶子的路径，共享前缀单独记录、只算一次；恢复追加的 Run 不计入 |
| 4 | Eval 之外的成功判定 | 标记验证命令 / 收尾时由程序跑验证器 / 人工确认 / 不做 | 任务或会话配置验证命令，尝试收尾后由程序作为独立子进程在该次尝试的工作区执行，三值口径同 058，落通用验证观察记录；未配置则标未知；人工确认暂不做 |
| 5 | 五个标签边界 | 见下 / 撞上限算放弃 / 无验证正常完成算疑似成功 | 成功只认验证通过（验证结论压过运行终态）；失败为验证失败，或无验证但为业务失败、撞任一上限、治理熔断；放弃为人主动取消（非熔断）；基础设施错误为失败分类中的基础设施错误；未知为缺运行结束记录、有悬账、验证未判定、无验证且正常完成；放弃与基础设施错误不进成败对比 |
| 6 | Run 内局部对 | 严格限定纳入 / 不纳入 / 全部纳入 | 纳入，只取理由来源为人写的拒绝与域错误后紧跟成功重试，只产出教训候选；系统默认文案、策略拒绝、环境异常与无来源字段的旧记录不用 |
| 7 | 提炼器执行体与触发 | 复用 worker 机制新增角色 / 另起执行体 / 与 Reviewer 合并 | 复用 worker 机制新增提炼器角色，只读、无工作区，只读工具作用域绑定一组尝试；候选走 M6 链路；并行同任务全部收尾后与分叉叶子完成验证后自动触发，另有 `pigeon distill`（可指定任务标识或 Eval 结果目录，只读读取其他治理根的会话）；Eval 不自动触发；预算单设（缺省 16 轮、5 分钟、80,000 token），与 Reviewer 共用全局并发闸 |
| 8 | 候选对比来源 | 候选升 v3 加对比来源块 / 写进正文 / 另建对比候选 | 候选升 v3，v2 字段不变，加法式新增对比来源块：成功侧与失败侧各自的尝试引用（治理根、会话、Run、条目范围）、分叉共享前缀范围、各侧标签与验证记录引用、产物形态（教训 / 流程 / 步骤集）；单来源候选该块为空 |
| 9 | 提炼器输入规模 | 沿用 M6 截断并按对比结构裁剪 / 全量 / 模型摘要 | 沿用 M6 单条工具结果截断；每侧上限 24,000 字符，超出从最早处丢弃并标注；任务描述只喂一次；分叉场景以分叉点为界，共享前缀只喂一次；独立尝试不做分歧步对齐；模型沿用角色表覆盖列 |
| 10 | 写穿方式 | 实时全量写穿 / 需要时从账本重建 / 分叉发生时才建树 | 分叉发生时才建树：账本先记分叉记录（分叉点的 Run 与序号、新分支标识、分叉点快照引用），再导入分叉点之前的历史，此后该会话实时写穿；树文件放治理根 `.pigeon/trees/`，为派生缓存，不 fsync、不阻塞主循环，可由账本重建；施工补耗时基准 |
| 11 | 工作区回到分叉点 | 每轮快照 / 文件变化后快照 / 只退对话 / 靠回执反推 | 仅在写操作或命令确实改变文件后，用 git 底层命令在临时索引上生成快照提交，挂 `refs/pigeon/checkpoints/<会话>/`，不触碰用户工作区、暂存区与分支；分叉时从分叉点之前最近的快照开独立工作树；非 git 工作区分叉明确报错，不降级 |
| 12 | 分叉发起 | 只手动 / 手动加失败自动分叉重试 / 再加智能选分叉点 | 手动分叉（cli 与 tui 主会话）加可选的失败自动分叉重试：`--retry-on-fail <K>` 缺省 0 关闭，按会话冻结并随注入快照与 run.started 落盘；尝试标为失败时从本次任务开始处分叉重试，最多 K 次，不注入任何提示，共用预算与全局并发闸；适用主会话与 `pigeon run`，并行同任务派发不叠加 |

## 权衡要点

- 第 1 件：自建会话树的主要工作量在接线（写穿、分叉续跑、工作区回退），上游已提供树存储、上下文还原与契约测试；两类素材互补——独立尝试回答整体做法差在哪，分叉回答从哪一步走岔。
- 第 4、5 件：成功只认确定性验证，是 §M7 完成证据"当前叶子没有验证时不会被标为成功"的直接落实；由模型运行的验证命令证据受模型控制，不取。
- 第 6 件：人写的拒绝理由是 006 定的负样本监督信号，066 的理由来源字段为此而设；产出形态限定为教训，满足"失败分支只产生失败案例"。
- 第 10 件：不分叉的会话零额外写入；账本中的分叉记录是会话树的权威来源。
- 第 12 件：从任务开始处分叉使分叉点确定；不注入提示是为避免与 042 冲突，并避免两条分支的差异混入"是否看到提示"。

## 施工期核实的上游事实（2026-09-19 补）

- 上游契约测试为 30 条用例，其 create 与 fork 调用不带 cwd，需按用例包一层独立临时根后运行。
- 上游 turn.completed 由助手消息的 message_end 归一化而来，早于该轮工具调用落定；会话树写穿因此不能以 turn.completed 为入队时机，否则丢失工具调用参数、与由账本重建的结果不一致。
- 快照记录的条目号取"当前条目号加一"，前提是上游在工具执行结束后紧接着发该工具结果消息；该前提由真适配器用例钉死，上游行为若变即精确变红。
