## 当前应记录的问题

### P2-1：固化配置规则的账本回指随 /revoke config#N 漂移，且配置移除在 Event Log 零留痕

两处互相放大的审计完整性缺口：

1. **回指不稳定**：`matchConfigGrants` 的 refId 是位置序号 `config:grants.json#<index>`（`grants.ts:88`），而 `removeGrantConfigRule` 用 splice 整文件重写（`grants.ts:191-196`）——删除第 N 条后其后所有规则序号前移。历史 intent 行的 `grantRef` 因此漂移或悬空。场景：规则0=`edit_file(src/**)`、规则1=`read_file`；上周一次写调用账本记 `grantRef=config:grants.json#0`；人执行 `/revoke config#0` 后原规则1 变成 #0——事后审计"这次写操作凭什么没问人"得到指向 read_file 规则的错误答案。
2. **移除零留痕**：`/revoke config#N`（`cli/grants.ts:128-134`）只改 grants.json，Event Log 无任何记录——grant.revoked 族只覆盖会话 grant（`grants.ts:276-286` 仅 SessionGrantStore.revoke 调用）。移除动作本身无审计痕迹，事后无法发现"曾经有一条规则、后来被撤了"。

决策 3 的头条增量承诺是"每次自动放行账本回指具体 grant/配置条目，可审计'这次写操作凭什么没问人'"——移除后该承诺失真。定级 P2：执行期授权判定本身正确（移除只影响未来求值面且有"下次会话生效"如实标注 `cli/grants.ts:131-133`），缺口在历史可追溯性，不阻断 M4 收口。修复方向：refId 携带稳定身份（如 promotedFrom.grantId 或规则级 uid，序号仅作展示）；配置移除/升格追加 Event Log 留证（新族或扩展 grant 族语义）。

### P2-2：D2"启动/冷恢复显式警告 + trace/replay 标注缺口"的冷视图覆盖不全

D2 原文："listenerErrors 非空时 CLI 启动/冷恢复显式警告 + trace/replay 对应位置标注缺口（可见降级，绝不假装证据链完整）"。as-built 三处覆盖缺口：

1. **"启动即查"恒为空转**：listenerErrors 是进程内数组，新进程启动时必为空（`repl.ts:77` 的启动检查永远不会触发）；跨重启的历史落盘缺口只能经对账/replay 标注间接呈现。D2 字面的"启动/冷恢复显式警告"对既往缺口无承载。
2. **trace 不渲染文件级撕裂尾巴**：`cli/trace.ts` 无 tornTail 呈现（grep 实证；replay 有 `cli/replay.ts:160-162`）。trace 视图下一个死于写盘中途的会话与干净会话在尾部不可区分。
3. **entry runSeq 断号无冷视图检测**：entry 写盘失败按 D3 不占位重试（`adapter.ts:364-375`），留下 runSeq 空洞（1,2,4…）；replay 逐条渲染 entry（`cli/replay.ts:112-113`）但不检测连续性，trace 完全不消费 entry 族。活会话内有 warnEvidenceGaps 兜底（`repl.ts:108`），冷视图无。

定级 P2：无证据丢失（torn tail 按未持久化容忍、entry 缺口入 listenerErrors、对账结论不受影响——崩溃矩阵测试证明），缺口在 D2 承诺的可见化覆盖度。修复方向：trace 运行头渲染 tornTail；replay 检测 runSeq 断号并标注；resume 冷恢复屏汇总呈现既往缺口（tornTail + 孤儿 + 待对账已有）。
