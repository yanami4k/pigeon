## 变异反向验证方法

沿用 M5 审计的执行器做法：`mut-run.mjs`（本地临时目录，不入库）把工作树的 src、package.json、tsconfig.json、biome.json、.dependency-cruiser.js 复制到一次性目录，`cmd /c mklink /J` 挂 node_modules，施加单点变异后跑 `node --test --test-timeout=20000 "src/**/*.test.ts"`，结束 `cmd /c rmdir` 拆联接；工作树与 node_modules 不被触碰，全程无 `git checkout -- <file>`。每个切片一个变异脚本（`m55s0-mutate.mjs` 到 `m55s5-mutate.mjs`），编号 0 为不变异基线，每次结果写同目录 `<变异脚本>-<编号>.log`。

"精确变红"的判读口径：变红集合里每一条都能由该变异直接解释，且不含与该机制无关的用例。一处变异被两道防线同时拦下时（例如构造扩权同时被派出前的子集校验挡住），两类用例都算精确，逐条说明。

## 已知边界与偏差（如实登记）

- Windows 下 npm 等 .cmd / .bat 入口不经 shell 无法运行，run_command 如实拒绝并提示改用可执行文件（例如 node 加脚本路径）；沙箱仍后置（048）。
- tester 的命令允许清单在工具执行时判定：审批面板对清单外命令显示警告，批准后仍被拒绝、不启动进程。
- 固化规则由人手工写入且不带 command 时，对 exec 档是工具级放行；[a] 与 /grants save 的正规路径恒带 command。
- /spawn /cancel /workers 只在 TUI 提供；cli REPL 顺序问答与并发 worker 审批互相抢输入，未接入。
- 主会话 Run 进行中时斜杠命令整体被 busy 语义拒绝（027），/cancel 也不例外。
- 收尾摘要只投影到 TUI 消息区与 child.settled，不注入父 agent 的上下文。
- 工作树放在主仓库的 `.pigeon/worktrees/` 下，主仓库 `git status` 会把 `.pigeon/` 列为未跟踪；"主工作区零改动"按已跟踪文件与文件内容判定。
- 派出时工作树已建而运行面装配失败，工作树保留由人清理；worker 正常收尾后工作树同样保留，供人审阅与合并。
- 会话打开锁以 pid 判存活，pid 被系统复用给无关进程时会误判为存活，报错给出锁文件路径供人工清理；grants.json 原子替换未 fsync 目录。
- 恢复 worker 会话要求父会话派出记录与工作树都在。
- 角色表档位列第一版全部继承全局值；OpenAI 兼容端点经 reasoning_content 映射 thinking 的线路仍未实测。

## 048 修订：Windows .cmd / .bat 启动器与经人确认的 shell（2026-09-14）

### 改动

- `src/tools/run-command.ts`：新增只读检查 inspectCommand，按命令判定三路执行——direct（参数数组直接 spawn）、launcher（Windows 下程序解析到 .cmd / .bat 且全部参数匹配保守字符集 `[A-Za-z0-9_.\-/:=@]`，经 `cmd.exe /d /s /c` 作启动器运行，脚本路径加引号、参数不再加工）、shell（含管道、重定向、串联、命令替换，或 .cmd / .bat 带字符集外参数）；.cmd / .bat 解析顺序为工作区根、PATH 逐目录，同目录 .exe / .com 优先。shell 路径要求治理层先以 authorizeShell 按调用授予确认、一次一用，未获授权即拒绝并写明原因（字符集越界时指出是哪个参数）；以 shell 运行时命令串原样交给 `cmd.exe /d /s /c`（Windows 以原样命令行拼接）或 `/bin/sh -c`。执行证据加 launcher 与 shell 两个标记，argv 记实际进程参数。原"解析到 .cmd 即拒绝"的分支删除。
- `src/application/governance.ts`：调用 inspectCommand 判定是否需 shell；需 shell 时会话 grant 与固化规则只在带 shell 标记时命中；放行路径（带 shell 标记的放权、yolo、人工批准）在放行前授予 shell；审批请求带实际命令串与 needsShell。
- `src/tools/grants.ts`、`src/approvals/grant-store.ts`：匹配加 shell 条件（需 shell 的调用只被 shell 为 true 的放权命中，精确字符串不变）。`src/state/grants.ts` 与 `src/state/event-log.ts`：固化规则与 grant.created / grant.promoted / grant.config-removed 加可选 shell（加法式，缺省即 false）；`src/state/materialize.ts` 生效集携带 shell；`src/application/grants.ts` 展示、升格与移除携带 shell。
- `src/state/receipt.ts`：exec 证据加 launcher 与 shell（v4 尚未发布，直接加为必填字段）。
- `src/approvals/handler.ts`：审批请求加 command 与 needsShell；execCommandLine 生成原样命令行（需 shell 时为「命令（经 shell）：…」）；[a] 文案需 shell 时为「本会话允许这条命令（精确匹配，经 shell）」；grantScopeFor 对需 shell 的命令带 shell 标记。`src/tui/approval.ts` 与 `src/cli/approval-ui.ts` 共用这些措辞；显示经各自输出边界的 036 净化。
