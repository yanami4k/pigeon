## 一、指纹与计数口径（305）

- 模块：`src/state/loop-guard.ts`（纯逻辑）。
- 一轮：一条助手消息里的全部工具调用与它们的返回结果。
- 指纹：各条调用按出现顺序，取工具名、参数的规范序列化（对象按键名递归排序，数组保序），以及按 toolCallId 对上的返回结果（正文与是否报错）。一轮内调用的先后不同即算不同。
- 豁免：豁免工具的调用与结果从指纹里去掉。去掉后为空的轮既不计数也不清零，前两轮的记录不动；与非豁免调用混在一轮时只比非豁免的。
- 没有工具调用的轮：两种计数清零，前两轮的记录一并清掉。
- 连续计数：与上一轮指纹相同计一次、连续累计，不同清零。
- 交替计数：与前两轮指纹相同且与上一轮不同计一次、连续累计，不同清零（两轮一循环 ABAB…）。
- 这一轮的计数取两者的大者。计数 N 表示已有 N 轮与前面重复：完全相同的轮从第 2 轮起计 1，计到 20 时是第 21 个相同的轮。
- 触发：计数从阈值以下升到阈值时各触发一次——到 remindAt 提醒、到 warnAt 再提醒、到 stopAt 叫停。模式变了计数即清零，之后再打转照常再次触发。
- 按 Run 计：换了 Run（终端界面里人发下一条、续跑、回炉的下一轮）即从零开始。

## 二、提醒送达方式（306）

- 运行面 `PiRuntimeAdapter` 新增整轮观察口 `subscribeRounds`：上游每轮结束（turn_end）时交出这一轮的调用（参数深拷贝）与结果（文本块拼接、是否报错）。它排在本轮待递通知转入 steer 队列之前。
- 提醒经运行面的通知队列 `notify` 递出：同一个 turn_end 里转入上游 steer 队列，模型在下一轮一定看到；上游随即写出这条用户消息的 message_end，会话记录里留作一条用户消息。送达路径与 worker 完成通知相同。
- 提醒以 `[打转提醒] ` 开头，写明重复的调用（工具名与参数摘要）与每条结果的前 3 行（每行至多 200 字，超出注"…（共 X 行）"；报错的写"报错："），说明重复不会带来新信息，引导换思路或停下总结。两轮一循环时首句改为"在两轮之间来回重复"，其下分"第一轮/第二轮"两段。第二次提醒另写明"如果再重复 K 轮，本次运行将被叫停"（K 为叫停轮数减当前计数）。
- 终端界面里提醒原文同时经消息区的系统行显示（与 worker 通知同一样式），不以人输入的回显（`> `）显示。

## 三、各入口的交代（307）

- 共用：`src/application/loop-guard.ts` 的 `attachLoopGuard` 把判定挂到运行面上，提醒经通知递出，叫停交给各入口。运行面中止原因与 Run 收尾的结束方式新增 `looping`（`src/state/session-entries.ts`），叫停时以此原因中止，Run 收尾条目记结束方式为打转。
- 终端界面（`src/tui/loop-guard-view.ts`，`src/tui/main.ts` 装配；`src/tui/shell.ts` 新增 `stopForLoop`）：消息区写明检测到打转、重复的调用与轮数，再走与 Esc 相同的中断路径（排队的输入退回输入框、不自动发出），中止原因为打转；会话照常可用。/resume 换绑后的会话同样挂上，运行面释放时摘掉。
- pigeon run（`src/application/headless-core.ts`，`src/cli/index.ts`）：新状态 `looping`，退出码 9（接在 8 之后）。叫停走与撞上限同一处中止：开了验证照常验证；开了回炉不再回炉（这一步以最后一次验证收尾）；等 worker 的收尾不再等。结果带 `looping`（计数与重复的模式），命令行在终态一行之后另起一行写收尾说明（--json 时在结果里）。失败自动分叉重试按标签触发，重试的每次尝试同样挂打转检测。
- 标签（`src/state/outcome-label.ts`、`src/state/session-judge.ts`）：一步的最后一个 Run 以打转收尾即算失败，排在验证结论之前——验证通过也算失败；证据不完整（缺收尾、有悬账）仍为未知。撞上限的判定集合同时加入 looping。
- worker（`src/orchestration/workers.ts`、`src/application/workers.ts`）：观察者工厂多拿到 worker 的运行面句柄；句柄新增可选的 `subscribeRounds`（就绪前订阅的在就绪后接上）。打转观察者 `loopGuardWatcher` 经 `control.stop("looping", 原因)` 叫停，worker 以失败收尾、错误类型 looping；叫停时中止原因为打转，worker 会话的 Run 收尾记结束方式为打转（其余观察者叫停照旧不带原因）。通知主 agent 套 271 的失败文字，原因写明重复的调用，末句"分支 … 上可能有部分改动"由失败文字给出。框架不自动重试。编排设定里开着才挂。
- 复盘（`src/application/memory-review.ts`、`src/application/runtime.ts`、`src/application/review-backfill.ts`）：压缩前、收尾与后台补做三种复盘都挂上。叫停以 `looping` 收尾，按撞上限对待（`hitLimit` 为真）：已写入的记忆保留；告警同一类只说一次；补做视同跑完——结束方式 looping 计入"跑完的收尾方式"，覆盖位置照常推进，不记失败，下次启动不再补。

## 六、说明文字（定稿）

- 第一次提醒：`[打转提醒] 最近连续 {N} 轮，你的工具调用和得到的结果都与上一轮完全相同：` + 调用与结果 + `重复同样的调用不会带来新信息。请换一个思路：核对前提是否成立、换一种做法，或先去读相关的代码与输出；确实做不下去，就停下来总结已经知道的情况和卡在哪里。`
- 第二次提醒：`[打转提醒] 这是第二次提醒。` + 同上首句与调用、结果 + `重复同样的调用不会带来新信息。如果再重复 {K} 轮，本次运行将被叫停。请立即换一个思路；确实做不下去，就停下来总结已经知道的情况和卡在哪里。`
- 终端界面叫停：`[打转] 检测到打转：连续 {N} 轮重复同样的工具调用与结果，本轮已叫停。重复的调用：{调用}。会话照常可用，可以给出下一步的指示；想让它接着做，直接说“继续”。`
- worker 失败原因：`打转，连续 {N} 轮重复同样的工具调用与结果，已被叫停。重复的调用：{调用}`
- pigeon run 收尾说明：`检测到打转：连续 {N} 轮重复同样的工具调用与结果，本次运行已叫停。重复的调用：{调用}`
- 复盘告警：`{压缩前复盘/收尾复盘/补做复盘}因打转被叫停：已写入的记忆照常保留，{这一步的结果不受影响 / 这个会话视同已复盘}`
