## 当前应记录的问题

### P1：Adapter 观察口存在引用逃逸

位置：`src/pi-runtime/adapter.ts` 的 `events()`、`transcript()` 和事件 listener 通知路径。

当前只复制顶层数组，事件 payload、transcript message/content 仍可能与内部对象共享。listener 也可能收到与内部保存对象相同的事件对象。

这不是路线图逐字写明的 M1 硬性验收项，也不是 M3 未施工项；它是 Adapter 封装和观察投影的边界缺陷。修复前应先补嵌套 `payload/content` mutation 行为测试，再决定采用深拷贝、冻结副本或其他隔离方式。不得仅凭 `structuredClone` 口头承诺，需确认实际 `AgentMessage`/`EventEnvelope` 数据形状和运行时兼容性。

### P2：Snapshot 模型身份可能被运行选项覆盖

位置：`src/pi-runtime/adapter.ts` 的 `options.model` 合并路径。

`options.model` 目前允许覆盖 `provider`/`id`，可能导致实际 Agent 模型与 `InjectionSnapshot.model` 不一致。

建议将模型选择放在 Snapshot 构造阶段；Adapter 只消费 Snapshot。若保留 `options.model`，它只能补充 `api`、`baseUrl` 等运行元数据，`provider`/`id` 应由 Snapshot 唯一提供，或在重复提供时拒绝。

### P2：`src/tools` 上游依赖豁免过宽

位置：`.dependency-cruiser.js` 与 `src/boundary-rules.test.ts`。

当前允许整个 `src/tools` 直接导入 `@earendil-works/*`，以支持后续工具工厂包装；当前已提交内容未发现工具目录自行构造/驱动 Agent 的实际违规。

这是未来规则防护缺口，不应在 M1 阶段为了收口而提前重构。待 M3 工具包装和 Adapter 接线稳定后，再将上游导入集中到受审计的桥接层，并增加 rogue Agent fixture。
