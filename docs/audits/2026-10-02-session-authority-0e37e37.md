# 会话权威链审计与核实（基线 0e37e37）

- 对象：claude/build-2-hooks 的 0e37e37（本轮五段施工合并后的交付分支）。
- 内容：一份针对会话权威链的审计报告的结论、逐条核实与处置。核实按 0e37e37 的源码进行，行号均指该提交。

## 一、审计报告的结论

权威链为单根：JsonlSessionRepo（写者）→ 会话文件 → src/persistence/session-reader.ts（唯一只读读取器，坏行容错、父链改接）→ 主分支条目 → 纯函数 fold。续接、分叉、放权种子、脚本续跑与续接报告都经这一条链。按四条判据：

| 判据 | 报告结论 |
|---|---|
| fold 唯一（实时与恢复同一路径） | 通过：运行侧不维护内存视图，每次判定先 flush 再重新读取并 fold |
| 分支感知 | 通过：视图都从主分支叶沿祖先链走，写者取分支用 pi 的 findEntriesOnBranch |
| 临时索引的失效时机 | 一处缺口（发现 ①） |
| 闭包逃逸 | 两处缺口（发现 ②、③） |

另记一条非问题：判定视图（storeSessionView）与显示视图（buildSessionView）是两个独立 fold，同源同分支、有测试锚定、决策 180 与 181 有记录；新增条目字段时两处须同步，属已知的维护耦合。

## 二、逐条核实

### ① 写者打开失败后核心留在注册表——报告所述情形不成立

- 报告：src/pi-runtime/session-store.ts 的 openCores 在打开失败后不摘除核心，同进程重试会命中它，之后整个会话的写入被静默丢弃；情形为续接时遇锁或读写抖动、重试后会话长时间运行而磁盘上无记录。
- 核实：
  - 打开失败时核心的 session 置为 undefined 并经 onFault 告警（session-store.ts:172–176），之后排队的写入在 session 为 undefined 时直接返回（:201、:221）。
  - 续接路径：restoreContext 在会话文件没有打开时抛错"无法还原对话上下文，续跑中止"（src/application/session-runtime.ts:127–134）；调用处捕获后先 disposeRuntime 再上抛（:224–231）；disposeRuntime 最后关闭写者（src/application/runtime.ts:924–938）；写者关闭使引用数归零并从 openCores 删除核心（session-store.ts:291–295）。同进程再次续接会新建核心、重新打开。
  - 结论：所述"重试命中失效核心、写入被静默丢弃"的情形走不通。
- 残余：新建会话时会话文件创建失败，按"写者从不抛、存储故障告警"的既有设计，告警一次后会话照常运行、不再记录。属既有设计，不作缺陷处理。
- 处置：作廉价加固——打开失败即把核心从注册表摘除，使此后同一会话的打开总是重新尝试。

### ② 交互会话续接后 worker 编排器为空——属实

- 报告：派出与收尾条目成对写入会话（缺收尾即进程中途退出），只有脚本编排从会话记录重建注册表；交互会话续接后编排器为空，查询、取消、取用上次运行的 worker 均找不到，工作树遗留无人认领。
- 核实：
  - 编排器的 worker 注册表只在内存（src/orchestration/workers.ts:491）。
  - take_worker 只按内存编排器的 status() 查找 worker（src/application/take-worker-tool.ts:95、:114）。
  - 脚本编排续跑时从会话视图的 children 重建调用记录（src/application/script-host.ts:151 起），交互会话续接没有对应做法。
  - 结论：上次运行中已收尾、尚未取用的 worker，续接后无法经 take_worker 取用；其工作树留在 .pigeon/state/worktrees 下。
- 处置：修复，见第三节。

### ③ worker 完成通知只在内存——属实

- 报告：worker 完成的通知等到下一轮才递入对话；若 child.settled 已写入、通知尚未递出时进程退出，续接后没有补递的路径。
- 核实：通知队列只在内存（src/pi-runtime/adapter.ts:241）；notify 只入队（:364），通知在下一次运行时取出并作为用户消息交给模型（:400），此后才随该轮写入会话。进程在入队与递出之间退出时，通知丢失，续接后不补。
- 处置：修复，见第三节。

## 三、修复要求（在 claude/build-2-hooks 上进行，结果追加于第四节）

1. 写者打开失败即从 openCores 摘除核心（加用例：同一会话首次打开失败后，再次打开会重新尝试并成功）。
2. 交互会话（终端界面主会话、pigeon resume 等续接入口）续接时，从会话视图的 children 重建编排器的 worker 记录：
   - 上次运行中已收尾且工作树仍在的 worker：查询状态与 take_worker 照常可用，状态里标明来自上次运行；
   - 只有派出、没有收尾的 worker：标为随进程退出而中断，不可取用；
   - 对上次运行的 worker 发取消、发消息、补批续做，返回明确的说明，不报"找不到"。
3. 续接时，对上次运行中已收尾、但其完成通知没有作为消息出现在主分支上的 worker，补递一条通知（通知文字带可识别的 worker 会话号，用于判定是否已递出）。
4. 第 2、3 条各有用例与变异验证；docs 里关于 worker 与续接的说明相应补充。
