### 待确认的取舍

- 旧会话的验证记录仍按旧结论贴"通过"标签（"读旧会话里的旧标签时照常显示"与"去掉通过"的直接折中）：倾向保留，选项是不再让旧验证记录参与标签现算（旧会话的通过标签会全部消失）。
- 多份尝试的收尾通知由主 agent 或人比较：`attempt` 文案里不再有任何结论词，各份标题为"第 N 份："。
- SessionStart 补的上下文以"并进第一条输入"的形式进入（前缀一段，标注来源）：决策说"以一条上下文消息进入"，但 headless 的第一条输入就是任务文本，做成独立消息要动会话存储；选项是给 adapter 加一条注入消息的通道（改动面更大）。终端界面同样前缀到第一条输入并在消息区提示一行。
- 收尾钩子到上限时 `HeadlessStatus` 记 `stop-hook-limit`，但底层 Run 的收尾条目仍是 `completed`（RunEnd 写下后无法回改）：结束原因体现在步结果、退出码与钩子记录里；选项是给 Adapter 加"改写下一次 RunEnd"的接口。
- `/reload` 时不确认的钩子条目按"变化即不启用"处理（与项目共享层放行规则同口径），不是"沿用原内容"：钩子以内容为标识，没有可对应的名字去还原。
