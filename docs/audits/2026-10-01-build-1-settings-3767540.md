### 5 第一道防线：.pigeon 为受保护路径

- application/protected-paths.ts：判定器。写入落在工作区根之内时只看工作区根自己的 .pigeon（worker 的工作树在治理根的 .pigeon/state/worktrees 下，树里的普通文件不算），落在工作区根之外才看治理根的 .pigeon；先词法判定，本地工作区再按真实路径判定（路径上已存在的最深一层 realpath 后拼回其余部分；.pigeon 本身是符号链接时其指向的目录同样受保护）；大小写不敏感的文件系统上按不敏感比较（翻转工作区根路径的一个字母探测，探不出时 macOS、Windows 视为不敏感）。容器工作区只做词法判定。
- application/governance.ts：对注册为写档且按工作区限定路径的工具（目前即 edit_file 两种模式），path 落在受保护路径上时放权（会话与配置）不参与求值、worker 自己工作树内的默认放行不适用；拒绝名单仍最先判定，yolo 仍放行。批准请求带 protectedPath。
- approvals/handler.ts 新增 protectedPathLine，cli 与 tui 的审批面板在工具名之后显示"受保护路径：…（…须逐次批准，会话放权与配置放权都不适用）"。
- application/runtime.ts 为每个运行面装上判定器（本地工作区 realPaths，容器工作区只词法）。

### 6 第三道防线：会执行命令的配置按内容确认

- persistence/config-trust-store.ts：~/.pigeon/state/config-trust.json，按项目规范化路径（realpath）+ 条目键记指纹；读改写在独占锁里、原子写入；记录畸形响亮失败。

- cli/index.ts：pigeon run 识别 --trust-config；--line 与 resume 用行内问答；tui/main.ts 在壳接管终端前问答。

## 七、待确认的取舍

1. 迁移落点：permissions 进项目个人一层，其余进项目共享一层。选项：全部进 settings.json / 全部进 settings.local.json / 按此分。理由：放权规则此前只由 /grants save 写入、是个人的，进可提交的 settings.json 会把个人放权带进仓库；其余各节原本就是项目配置，进项目共享一层才能按 325 提交共享。
2. sandbox 一节跨层也按通则合并，合并后 image 与 dockerfile 同在即报错（例如用户级给 image、项目级给 dockerfile）。选项：sandbox 一节整体由高层替换。理由：与"对象按键逐层合并"的通则一致、不设例外；报错指出组合问题，人可在高层显式写清。
3. 指纹范围：MCP 服务按合并后的启动定义计，含设置 mcp 一节里给了 launch 的服务与 http 型服务（http 型只连接、不执行命令）。理由：施工说明写"每个 MCP 服务的启动定义"，按字面全部纳入，代价是 http 型也要确认一次。
4. "本次不用"沙箱配置时，沙箱会话照常开始、改用 Pigeon 自带的通用镜像（启动时有一行"本次不用…"提示）。选项：拒绝开沙箱。理由：说明写"沙箱不用该配置"；通用镜像不可用时开沙箱照常如实报错。
5. update_memory 不算写入类文件工具，不受第一道防线约束。理由：它是记忆专用工具（无 path 参数，只写 .pigeon/state/learned），331 定为写入不审批；受保护路径只针对按工作区限定路径的写档文件工具（目前即 edit_file）。
6. 容器工作区（沙箱）只做词法判定，容器内写成绝对路径（如 /workspace/.pigeon/...）的写入不在判定内。理由：宿主上的 realpath 对容器路径无意义；工具参数以相对路径为主。改法若要补上，需把容器工作区根传给判定器。
7. 受保护路径的批准面板仍提供 [a]/[d] 键；由此建出的放权对受保护路径不生效（面板上写明）。选项：受保护路径隐去 [a]/[d]。理由：改动最小，放权对其余路径仍有用。
8. 确认记录（config-trust.json）畸形时响亮失败而不是当作空记录。理由：与其余配置的 fail-closed 一致，避免掩盖文件被改坏。
9. .pigeon/.gitignore 在会话开始（建 .pigeon/state/ 时）与第一次建 settings.local.json 时确保，不在各写入点（会话存储、记忆、工作树等）各自判断。理由：会话开始即会建状态目录，集中一处易于维护。
10. 装配层（buildRuntime、openSessionRuntime、runHeadless）不给快照时用空快照、不读任何设置文件；日常入口一律显式给出。理由：测试与跑批器不读使用者的设置，worker 与派生运行面一律沿用父快照，避免"缺省自读"把中途重读带回来。
11. 信任目录里的 ~ 按用户主目录展开；比较用两边的 realpath，大小写不敏感的平台（macOS、Windows）按不敏感比较。
