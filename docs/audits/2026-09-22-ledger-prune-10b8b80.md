# 账本剪边角（决策 128，基线 10b8b80）

范围：退役四种无读者或与别的记录逐字重复的记录（候选筛查、提炼跳过、固化升格、固化移除），删除 M3 旧账本的一次性转换。账本主体、`llm.request`（044）与其余记录族不动；trace 在候选审批后状态不更新的问题不在本轮范围。

## 一、退役四种记录

| 种类 | 原写入方 | 原读取方 | 处理 |
|---|---|---|---|
| `candidate.screened` | `review/candidates.ts`、`distillation/candidates.ts` | 候选状态现算、trace 候选行的命中列表、replay 时间线 | 停写；状态与 trace 改读 `candidate.proposed` 内嵌的 `candidate.scan`；replay 的候选提出行补上扫描器版本与命中项 |

盘点口径核对：四种记录的读取方只有上表所列，没有发现别的消费者；候选筛查的每一个字段都能从同一次写入的候选提出记录里逐字取到（两个写入方都用 `candidate.scan` 填筛查记录）。

随之移除：四个 schema 与类型、四个追加输入类型、`JsonlEventLog` 的四个追加方法、物化会话里的四个数组（`candidateScreeneds`、`distillSkippeds`、`grantPromoteds`、`grantConfigRemoveds`）、引用型记录集合里的 `candidate.screened`、`ProjectedCandidate.screened` 字段、replay 的四个渲染分支、`GrantConfigEventSink` 接口与 `GrantsCommandContext.eventLog`（cli 与 tui 两处装配一并删除）。

放权命令：原先"扩权先留证后生效、缩权先生效后留证"的两段顺序随留痕消失，升格与移除都只剩一次配置文件操作。固化规则的稳定身份仍是 `promotedFrom.grantId`，配置规则命中的回指口径不变（`cli/grants.test.ts` 的移除用例仍断言移除前一条规则后，后一条规则的回指逐字不变）。

分叉组提炼：跳过时原本要打开来源会话文件只为写跳过记录，现在在打开之前就返回跳过原因，不再为此争用来源会话的写入锁。

并行派发的收尾报告原先写"不提炼：<原因>（已记提炼跳过）"，括注不再成立，已删去。

## 六、`Proposed` 状态的可达性

退役前，候选状态在"有提出记录、无筛查记录"时为 `Proposed`，只可能出现在两次写入之间进程死亡或筛查写入失败时。退役后状态只读提出记录内嵌的扫描结果，而 `candidate.proposed` 自引入起内嵌的候选 schema（v2 与 v3）就把 `scan` 列为必填，v1 迁来的保留形状不会出现在提出记录里，因此投影不再产出 `Proposed`。生产代码里 `Proposed` 只剩状态枚举与 trace、候选列表两处的中文标签；待审计数（`PENDING_STATUSES`）本就不含它。枚举值未删，待裁。

## 九、撞上限观察记录只在运行确以中止收尾时写（072 修订）

现状：`application/headless-core.ts` 与 `orchestration/workers.ts` 在上限触发的那一刻（最后一次 `turn.completed` 到达、或墙钟定时器到点）先写 `run.limit-hit` 再发中止请求。中止请求到达时模型若已自然收尾（恰好用满最后一轮），运行终态是完成，账本里却留着撞上限记录，标签按 072 判为失败。

改法：上限触发时只发中止请求、记下撞到的是哪一种上限；等 `run()` 返回，终态确为中止且不是人主动取消时，才写撞上限记录。运行已结束，运行面的当前 Run 已清空，因此运行面句柄的 `run()` 与 `continueRun()` 返回值带上 `runId`，`recordLimitHit` 与 `PiRuntimeAdapter.recordObservation` 增加可选的 `runId` 参数，记录落在被中止的那次 Run 上。未开跑即被中止的运行（运行面尚未就绪）没有 Run，不写。

写入时序随之变化：撞上限记录由中止之前移到运行收尾之后，在账本里排在该 Run 的 `run.ended` 之后。标签现算按 Run 取记录，与顺序无关。代价是：进程若死在运行收尾与补写记录之间，这次运行会带着 `run.ended` 却没有撞上限记录，标签现算为放弃（不进成败对比），而不是失败。

测试（先写，改实现前均按预期变红）：

- `application/headless.test.ts` 新增：只答一句、上限 1 轮，终态完成，账本里没有撞上限记录，标签为未知（未配验证命令）而不是失败。原有的上限中止用例补断言：记录落在本次运行的 Run 上。
- `orchestration/workers.test.ts` 新增：假运行面跑满 3 轮后自然完成，以完成收尾、不写记录；墙钟上限中止照写，且落在该 Run 上。原有的轮次上限用例补断言记录的 Run。
