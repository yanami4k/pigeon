## 一、多行输入与历史（`src/tui/input-editor.ts`、`src/application/prompt-history.ts`）

- 输入框由 pi-tui 的单行 `Input` 换成同版本（0.84.4）自带的 `Editor`。补全不接（不设补全提供者）。边框横线与滚动提示经 `borderColor` 换成 ASCII（`-`、`^`、`v`），界面自有部分仍只用 ASCII。
- 键位取 pi 缺省：Enter 发送；换行为 Shift+Enter 与 Ctrl+J（`tui.input.newLine`），Editor 另认 Alt+Enter 与"行末反斜杠再按 Enter"。Windows Terminal 缺省不区分 Shift+Enter，Ctrl+J（送 `\n`）与反斜杠回车在其中总是可用。
- 粘贴：括号粘贴模式下原样保留换行，CRLF 与 CR 归一为 LF。超过 10 行或 1000 字符的粘贴按 Editor 自带方式折成 `[paste #n +k lines]` 或 `[paste #n k chars]` 标记，发送时展开为原文（回显与提交的都是原文）。
- 历史：↑ 在输入框首行（空、光标在行首或正在翻历史时）翻上一条，↓ 在末行翻回；多行条目原样取回。发送的与排队的输入都进历史，拒绝理由不进。
- 跨启动保留、按项目分开：存在项目治理根的 `.pigeon/tui-history.json`（`{version:1, entries:[...]}`，从旧到新），不进会话记录与账本。上限 100 条（与 Editor 内置历史上限一致），连续重复只记一次。每次追加前现读文件再写（同一项目同时开几个界面时不覆盖对方刚加的），写临时文件后改名。文件缺失或畸形按空历史处理；写失败静默放弃。
- Ctrl+C 单击清空输入框（含多行）的语义不变。

## 二、状态栏（`src/tui/status-bar.ts`、`src/application/session-cost.ts`）

- 位置：输入框下方一行（Claude Code 惯例）；之后的编排面板同在输入框下方（决策 301）。原"state: …"状态行与 worker 行仍在输入框上方，未动。
- 内容与写法：`<provider>/<模型号> | ctx <百分比>% (<token>/<窗口>) | cost <花费> | backfill <第几个>/<共几个> <花费>`。数字 1000 以上写作 `k`、百万以上写作 `M`。
- 上下文用量：运行面新增 `contextUsage()`，取与压缩判据同一口径的 token 数（最近一次正常助手回复的用量，加其后消息的字符估算；压缩摘要之前的用量视为过期）对模型窗口（压缩配置里的 `contextWindow`）算百分比。每轮收尾、压缩提示、运行收尾、换绑时重取，压缩后随之下降。
- 本会话花费：价格来源是模型回复自带的 `usage.cost`（金额单位同其价格表，显示为 `$`）。组成：
  - 主 agent：每条 `turn.completed` 的用量；
  - 工具执行中另发的模型请求（web_fetch 的提炼等）：工具结果 details 的 `modelUsage`；
  - 本会话派出的 worker 与从本会话分叉的复盘：会话打开之后新出现、且已收尾的子会话，在运行收尾、压缩提示与 worker 在跑个数减少时读其会话记录计入，每个只计一次；在跑中的 worker 收尾后才计入；
  - 续接会话（`--continue`、`--resume <id>`、/resume 换绑）：从会话记录累计已有花费——主会话自己的消息，加父会话是它的 worker 会话与带复盘标记的分叉会话。
  - 不计入：/fork 分支与失败自动分叉重试（独立会话）；后台补做的复盘（补的是别的会话）。
- 没有价格：用了 token 而价格为零的部分单列，写作 `12k tok (no price)`；与有价格部分并存时写作 `$0.5000 + 12k tok (no price)`。
- 后台补做进度：正在补某一个时显示 `backfill 2/5 $0.0100`（有失败时加 `n failed`），金额为这次启动已补完的复盘的累计花费，不并入本会话。消息区不再逐条写进度，结束时只留一行：有失败时 `后台补做复盘：n 个失败，留待下次启动重试（首个原因：…）`，全部补成时 `后台补做复盘：全部补完（n 个，花费 …）`，没有要补的不说。补做本身出错的一行原因照旧。
- 结构化进度（`review-backfill.ts` 的 `observe`）：开始前、开始补第几个、每补完一个各给一次；花费读补做复盘会话的记录。原有 `progress` 一行文字保留（终端界面不再订阅）。
- 窄终端：不折行，按优先级截断——先把各段换成短写法（`ctx 25%`、`$1.23`、`backfill 3/5`），再依次去掉补做进度、模型、花费，上下文用量留到最后，仍放不下时按显示宽度硬截。

## 三、工具调用结果（`src/tui/tool-output.ts`、`src/tui/message-flow.ts`）

- 运行面新增只读观察口 `subscribeToolResults`：工具结果消息落定时交出结果文本（文本块拼接）与 details 的深拷贝，带 runId；不落盘、不进事件序列、不改 `tool.settled` 载荷与会话记录。壳只认当前运行的结果。
- 显示在调用行下方，与调用行同一个 Text（每消息一个 Text 的纪律不变），行首 `  | `。
- 缺省收起：前 3 行（单行超过 200 字符截断），其后 `... +k lines (ctrl+o to expand)`。
- Ctrl+O 一次展开或收起全部，此后到达的结果按当前状态显示。展开后上限 200 行或 20000 字符，超出注明 `... truncated: k more lines not shown (limit 200 lines / 20000 chars)`；未超出时末行 `(ctrl+o to collapse)`。
- 编辑类工具：结果 details 带 `diff`（edit_file 的两种编辑模式都带）时显示 diff 而不是回执文字。
- /resume 换绑后回放的历史沿用原有投影，不含工具结果块。

## 四、运行中排队与查看类命令（`src/tui/input-queue.ts`、`src/tui/command-table.ts`）

- 运行中（含 /compact 压缩中、/resume 续跑流程中）提交的普通输入进队列，不再按决策 027 拒绝。排队内容显示在输入框上方（每条首行，多行加 ` ...`），末行提示按键。
- 空闲后自动发出，多条时按 pi 惯例逐条：一条跑完再发下一条，不合并；即时完成的命令（如 /grants）不占住，接着发下一条。
- 退回输入框：Alt+Up（另认 Alt+Q，同 pi 在 Windows 下的缺省）随时把全部排队内容退回输入框；Esc 中断时同样退回，中断后不自动发出。退回的文本为各条排队内容在前、输入框里已有的草稿在后，空行分隔（pi 惯例）。

## 五、续接会话（`src/tui/continue-flags.ts`、`src/application/recent-sessions.ts`、`src/tui/session-picker.ts`）

- 可续接的主会话：文件头没有父会话、且不带复盘标记的会话（worker、/fork 分支、复盘会话都不列）。每行：最近活动时间（最后一条消息的写入时刻，本地时间）、轮数（输入条数）、沙箱标记 `[sandbox]`、首条输入前 60 字符（换行压成空格）；按最近活动从新到旧。沙箱会话按 `pigeon/sandbox-<会话号>` 分支或开箱起点引用认出（一次 `git for-each-ref`）。
- `pigeon --continue`：接本项目最近的、至少跑过一轮的主会话；本机启动只接本机会话，带 `--sandbox` 只接沙箱会话。没有时在接管终端前说明一行并开新会话。
- `pigeon --resume <id>`：启动时直接打开该会话（不另建空会话），续跑报告与 /resume 同一份，会话不存在、旧格式在接管终端前报错。沙箱会话须带 `--sandbox`，本机会话不能带 `--sandbox`，不符即报错并给出用法。沙箱续接沿用开箱的续跑选项。
- `pigeon --resume`（不带 ID）与 `/resume`（不带 ID）：弹出会话列表（输入框上方）；↑↓ 选（循环）、Enter 进、Esc 退；打开期间按键归列表，输入框内容不动。当前会话与一轮都没跑过的会话不列。选中后按 `/resume <id>` 同一流程换绑；选中沙箱会话时给出 `pigeon --sandbox --resume <id>` 用法、不换绑。带 `--sandbox` 而不带 ID 时报错要求给会话号。
- `/resume <id>` 的用法不变；目标是沙箱会话时同样给出用法、不换绑。
- `--continue` 与 `--resume` 互斥；两者在交给启动参数解析之前取出。顶层帮助补了两行。

## 六、已知小毛病

- 运行期告警：`openSessionRuntime` 新增可选 `warn`，传给会话存储（`storeWarn`）、压缩前复盘（`learnedMemory.review.warn`）与工作区快照（`attachCheckpoints` 的 `warn`）；worker 与补做复盘的运行面经 `storeWarn` 同样接上。终端界面入口用 `switchableWarn`：壳接管终端期间落消息区，之前（启动告警、MCP 与沙箱提示）与停止之后照旧写标准错误输出。去重（同一类只说一次）与文案仍由各告警方负责。压缩提示本来就在消息区，未动。
- 恢复菜单：`askMenuChoice`、`PendingMenu` 与 1/2/3 单键决议自决策 183 起已无调用方（全仓检索只剩壳内定义与模态模块），连同状态行里 `answer in message area` 的提示删除。
- 过时的命令提示：斜杠命令集中到命令表，未知命令列出的可用命令按本会话实际可用的从表生成（含 /fork、/take、/export 等按条件出现的），/resume 的用法提示从表取；不带编排面时不再列 worker 命令，不在沙箱里不列 /export。`WORKER_COMMANDS_HINT` 随之删除。
- 缩放重绘：虚拟屏夹具的 `MockTerminal` 加 `resize`，经 pi-tui 的缩放回调触发重绘；新增用例断言变窄后行宽不越界、消息区内容零丢失、输入框内容保留、状态栏仍是一行，变宽后状态栏恢复全写。
- 1 万条消息渲染耗时（服务器，宽 120，1 万条消息其中 2500 条带 20 行工具结果，连跑 3 次）：首次渲染（全部折行）约 690 ms；再次渲染（未变消息命中缓存）约 1.7 ms；追加一条后约 1.0 ms；Ctrl+O 展开全部后约 1.1 s；换宽度（缩放）后约 1.5 s。流式输出与追加消息不卡；展开全部与缩放在 1 万条量级有约 1 秒的停顿，本段未处理。
- agent 派出的 worker 不刷新状态行：未修（编排一段）。

8. 看输入框下方一行 → `<provider>/<模型> | ctx n% (…) | cost $…`；跑一轮后百分比与花费增加；/compact 后百分比下降。
9. 把窗口拖窄到 40 列左右 → 状态栏只剩 `ctx n%` 等短写法、仍是一行；输入框与消息区不错位；再拖宽恢复全写。
10. 让 agent 读一个长文件 → 调用行下方显示前 3 行与 `... +N lines (ctrl+o to expand)`；按 Ctrl+O 展开，再按收起。若 Ctrl+O 没反应，记下终端是否截走了该键。
11. 让 agent 改一个文件（yolo 或已放权）→ 调用行下方显示 diff 的前几行，Ctrl+O 看全。
12. 发一个长任务，运行中输入 `下一步` 并 Enter → 输入框上方出现 `queued: 下一步`，本轮结束后自动发出。
13. 运行中再排一条，按 Alt+Up → 排队内容回到输入框可改；若 Alt+Up 无效，试 Alt+Q。
14. 运行中排一条后按 Esc → 本轮中断，排队内容回到输入框，不自动发出。
15. 运行中输入 `/sessions` → 照常列出；输入 `/compact` → 提示运行中不能用及原因，命令留在输入框。
16. 在有旧会话的项目里运行 `pigeon --continue` → 直接接上最近的会话，消息区有续跑报告与历史，状态栏花费从已有花费起算。
17. 运行 `pigeon --resume` → 弹出会话列表；↑↓ 移动 `>`、Enter 进入选中的会话；再开一次按 Esc → 提示已取消、留在新会话。
18. 在界面里输入 `/resume` → 同一列表；沙箱会话带 `[sandbox]`，选它 → 提示用 `pigeon --sandbox --resume <id>`。
19. 在启动后有待补做的会话时观察状态栏 → 出现 `backfill k/n $…`，补完后消失，消息区只有一行"全部补完"或失败说明。
20. 运行中若出现会话存储或复盘告警 → 告警在消息区成行出现，界面不被打乱。
