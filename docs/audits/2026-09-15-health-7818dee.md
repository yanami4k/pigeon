## 发现

### 一、文档与索引滞后（高：误导导航）

1. decisions.md 010、019、020 的锚点仍写 `src/cli/grants.ts`，015、021、023 仍写 `src/cli/session.ts`，两个文件已删除；对应代码现在在 `src/application/grants.ts`、`src/application/session-list.ts` 与 `src/application/resume.ts`。
2. ROADMAP §4 模块图把已建成的 `tui/` 列在"占位（export {}，按里程碑填充）"分组下；关键状态流写失败分类在 `src/persistence/classification.ts`，实际为 `src/state/classification.ts`（decisions.md 017 写的是对的）；pi-runtime 写依赖 state / tools / approvals，实际只依赖 state 与 tools；cli 与 tui 对 pi-runtime、approvals 的直接类型依赖未写入；`application/session-list.ts`、`grants.ts`、`workspace.ts`，`tools/edit-mode.ts`、`replace-edit.ts`，`state/candidate.ts` 未出现在模块说明中。
3. ROADMAP §M2 已知缺口仍列"工具调用轮在消息区留一个空行（登记不动）"与"/grants 长输出重复行（待验）"，前者已由 035 解决，后者在 m2 裁决记录中已判不可复现；§M5 已知缺口仍列"推理档位未配置""read_session_entry 与 load_skill 的域错误不进判据"等条目，均已由 050 关闭，未标注。
4. `pi-runtime/snapshot.ts` 注释称 receipt 与 event-log 没有迁移注册表，已不成立（`state/receipt.ts`、`state/event-log.ts` 均有注册表）。
5. `tui/main.ts` 有一个未使用的导入（biome 唯一警告）。

### 二、分层规则覆盖面不足（中：现在零违规，但部分回归不会被 `npm run deps` 抓到）

1. state、persistence、tools、approvals、memory、skills、mcp、application、eval 用允许清单；pi-runtime（`pi-runtime-no-storage-or-actors`）、execution（`execution-no-runtime-or-actors`）、orchestration（`orchestration-below-controller`）只列禁止目标，例如 pi-runtime 引用 application、orchestration、eval、memory、mcp、skills 不会报违规。
2. cli 与 tui 只受 `actors-no-execution` 与 `actors-no-persistence-writes` 约束：两个 Actor 互相引用不受限；`actors-no-persistence-writes` 只列 `legacy-migration.ts` 与 `grants-config.ts`，cli 的 trace 与 replay 引入了 `persistence/event-log.ts` 的写入类 `JsonlEventLog`（目前只用其静态 `filePathFor`），构造写入实例不会被规则拦下。
3. 占位目录与 `src/index.ts` 没有分层规则；`application-is-controller` 与 `eval-below-actors` 未放行 `review/`，M6 开工需改规则。
4. 边界元测试 `src/boundary-rules.test.ts` 覆盖 17 条规则中的 4 条；"巡航不空转"的判据为模块数大于 15（实际 271）。

### 三、入口与装配层重复（高：缺省值已出现不一致）

1. 模型与运行参数解析在 `cli/index.ts`（`parseModelFlags`）与 `tui/main.ts` 各写一份；缺省值已不一致：cli 为 provider `custom`、model `cli`，tui 为 `unknown`、`unknown`；tui 读取 `PIGEON_STREAM_FN` 环境变量，cli 的参数解析不读，但 cli 的报错文案提到该变量。
2. `buildWithMcp` 在 `cli/index.ts` 与 `tui/main.ts` 各有一份相同实现；MCP 启动与启动提示、buildRuntime 依赖对象、grants 上下文、resume 流程在 cli 与 tui 中重复二到三份。
3. `.pigeon/sessions` 路径除 `application/workspace.ts` 的 `sessionsDirOf` 自身外，还在 11 个生产文件中手工拼接 12 次。

### 四、职责过重的文件（中）

1. `tui/shell.ts`：主体是一个约 650 行的类，包含生命周期、按键处理、审批模态、斜杠命令路由、worker 命令、resume 与会话换绑、事件与增量渲染；可按斜杠命令分发、resume 控制、worker 面板拆分（与 M6 前置"shell 拆分"一致）。
2. `cli/index.ts`：子命令分发加 trace、replay、会话列表、run、eval、eval compare 各入口、参数解析、resume 接线、MCP 启动与 Eval 缺省 Skill 目录选择；可按子命令拆分并抽出共享参数模块。
3. `application/governance.ts`：放行排律、exec 与 shell 检查、熔断、四族账本写入同在一个类；熔断与账本写入可拆出，放行排律保持完整。无同名测试文件，经 19 个 adapter、cli、tui 等测试间接覆盖。
4. `tools/run-command.ts`：除工具本身外含 `planMcpLaunch` 与环境变量白名单，`mcp/transport.ts` 因此依赖 run_command 工具文件；进程启动策略宜独立成模块。
5. `persistence/event-log.ts`：18 个模块引用，集写入、幂等索引、会话列举、路径辅助与物化入口于一身；17 个 `appendX` 方法结构几乎相同。

3. "grants.json 的生产写入方只有两处"（ROADMAP §M4 完成证据）目前成立，但无测试或规则守护。
