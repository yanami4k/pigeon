- `orchestration/workers.ts`：工作区提供者按角色规划，reviewer 规划为无工作区，不建工作树、不建分支、收尾无需清理；运行面可选提供结构化结果，随收尾回收；状态里的分支对无工作区缺省。
- `orchestration/roles.ts`：新增可选的模型接入覆盖列（插件路径、provider 与 model 标识），四个角色缺省留空；reviewer 默认工具换成两个只读快照工具。角色策略的两条既有断言随之更新。
- `application/workers.ts`：无工作区时工作区根取治理根；覆盖列在场时该角色改用预加载的插件与覆盖的标识；按末条回复解析结构化结果（可带 json 围栏，解析不了视为没有）。
- 联合带来的编译面：cli trace / replay 的分支渲染与可选改动文件、Eval 快照的工作区窄化（Eval 必须是工作树，否则响亮失败）、worker 恢复作用域对无工作区直接取治理根，以及几处测试的取值窄化。

### S1 只读快照与工具白名单（064 子裁决 ⑤）

- `review/snapshot.ts`：被审 Run 的冻结快照——正文取自旁置内容文件按 Run 与条目号排序，工具调用取单 Run Trace 投影，Receipt 摘要按 Run 回记录上过滤；单条正文超过 2,000 字符头尾保留、中间标注省略字符数，整份超过 24,000 字符从最早处整条丢弃并标注省略条数与字符数；增量起点另带 4 条前情；落盘时已截断的正文如实标注。
- `review/tools.ts`：`review_snapshot` 读冻结快照（首读构建后复用同一份），`review_entry` 按条目号回查被审 Run 的原文；参数里没有会话或 Run 入口，作用域在装配时绑定；两者 read 档、不触碰路径参数。
- `state/review.ts`：工具名、审阅配置 schema 与审阅目标类型（放 state 叶子层，编排层与 review 层共用，不成环）。
- `persistence/session-read.ts`：只读面补转导出内容文件读取器。
- 分层规则：review 从占位规则移出，新增 `review-below-controller`（只依赖 state、tools、persistence 的只读物化）；application 放行 review。

### S2 调度器（064 子裁决 ①②④）

- `review/scheduler.ts`：纯调度——按 Run 计轮，每 N 轮触发（缺省 8），Run 结束固定补一次，N 为 0 只在 Run 结束审；全局闸同一时刻 1 个，上一次未收尾则跳过并交给跳过记录；派出抛错与收尾失败一律吞掉并上报、闸必释放；预算缺省 12 轮、3 分钟、40,000 token。
- worker 上限新增可选 token 项与 `token-limit` 收尾状态，编排层按 turn.completed 的用量累计；读用量对事件形状做可选链防护（替身事件不带 payload 时不能把 worker 打成失败，这是施工中发现并修正的实现缺陷）。
- 注入快照 v5 → v6，顶层新增可选审阅配置；run.started 随之带审阅配置；迁移完整性机检与快照测试登记 v5 → v6。
- `application/review-runtime.ts`：审阅派发器（专用编排器只派 reviewer，派出与收尾写被审会话，完成才落盘候选）与主会话调度挂载（订阅 turn.completed / run.ended，跳过落 review.skipped，派出时回指被审 Run）。
- `application/session-runtime.ts`：新增审阅选项，配置冻结进快照；只对作用域不是 worker 的主会话挂调度；挂载的停止动作登记到运行面释放前执行。
- 入口：`--review-every <N>` 与 `--no-review` 只在 cli REPL / resume 与 tui 接受；run 与 eval 按未知参数响亮失败。
- Reviewer 的两个只读快照工具不在主会话工具清单里，按"只读且只绑定父会话自己的那一次 Run"豁免子集约束（父策略的 deny 照旧生效，其余工具照常受子集约束）。

### S3 候选落盘与扫描（065 及其子裁决）

- `state/candidate.ts`：候选 schema v2 只放不可变元数据（种类、名字、内容哈希与字节数、来源四项、摘要、判断强度、扫描结果、取代关系），拒绝多出来的字段（状态不入 schema）；状态枚举新增 ScanRejected；v1 → v2 迁移注册表进机检表。
- `state/candidate-status.ts`：状态由提出与筛查两族现算——只有提出为 Proposed，筛查无命中为 SecurityScanned，有命中为 ScanRejected。
- `state/event-log.ts`：新增 candidate.proposed（候选元数据全文、审阅所用模型、轮次与 token 用量）与 candidate.screened（扫描器版本、命中项、可选模型筛查标注）两族，新增 review.unparsable 观察族；冷物化、Trace 单 Run 视图、replay 与 cli trace 同步呈现候选、跳过与不可解析记录。
- `review/scan.ts`：确定性规则——Unicode Tags、零宽、双向控制、变体选择符；中英文注入短语；curl / wget、常见密钥形态、IP 直连与回传服务、查询串带凭据的 URL；scripts/ 与 bin/ 目录及可执行扩展名。
- `review/candidates.ts`：typebox 校验结构化结果，不合格只记 review.unparsable、不落文件；按正文 sha256 定目录 `<名字>-<哈希前 16 位>`，同哈希跳过（不写文件、不记账）；先写同级临时目录再整体改名；同名不同哈希标记取代最新的旧哈希；Skill 为 SKILL.md、Memory 为 `<名字>.md`、Policy 为 SUGGESTION.txt；来源内容摘要由支撑条目在账本里的正文回指哈希算出；写好文件后依次记提出与筛查。
- `review/prompt.ts`：Reviewer 任务说明（只读、先读快照、按条目号回查、最后只输出一个 JSON 对象），输出格式与解析 schema 同源。

### S4 入口（064、065 子裁决 ⑤）

- `application/review-command.ts` 与 `pigeon review <sessionId> [--run <runId>]`：对冷会话手动补审，与自动审阅同一派发器；缺省审最后一个 Run；父策略取被审 Run 的 run.started；Reviewer 自身会话拒审；会话或 Run 不存在响亮失败。
- `application/candidates-list.ts` 与 `pigeon candidates [--all]`：跨会话现算候选，一候选一行（种类、名字、哈希前缀、状态、来源、时间），缺省隐藏扫描拒收并提示隐藏条数。

## 真实链路（Kimi For Coding）

驱动：会话运行面装配、yolo、审阅间隔每 2 轮；主会话给一个带项目约定的小任务（照约定给 package.json 新增类型检查脚本并在笔记里登记），第一个 Run 的审阅收尾后再问一句不调工具的问题。

| 项 | 结果 |
|---|---|
| Run 1 | completed，4 轮，12 秒 |
| 中途触发 | 第 2 轮与第 4 轮各派出一次 Reviewer（均 completed，3 轮与 2 轮，交回空候选） |
| Run 1 结束补审 | 被跳过（第 4 轮那次审阅尚未收尾），落 review.skipped |
| Run 2 | completed，1 轮 |
| Run 2 结束补审 | 派出并 completed（2 轮），产出 1 个 Memory 候选 |
| 派出记录 | 三次均为 reviewer、无工作区、所属 Run 正确、预算 12 轮 / 180 秒 / 40,000 token |
| Reviewer 广告工具 | 仅 review_snapshot、review_entry |
| 候选 | memory/npm-script-registration-convention，扫描无命中、状态已扫描、判断强度 0.85；正文与 candidate.json 按哈希落在暂存目录；主会话记提出与筛查各一条 |
| trace | 主会话列出三个 Reviewer 并给出进入命令；Run 1 行下列跳过记录，Run 2 行下列候选 |
| 内部故障 | 0 条 |

候选样例（正文）：

```markdown
# npm 脚本登记约定

新增 npm 脚本时，除了修改 package.json，还要在 NOTES.md 末尾的「脚本清单」中登记一行：`脚本名：用途`。

脚本名必须使用短横线小写（kebab-case）格式。
```

第一次真实链路（任务过于简单）两次审阅都交回合法的空候选，同时暴露派出记录缺所属 Run 的缺陷：派发器没有把被审 Run 交给编排器，trace 只能把 Reviewer 挂在会话层。已先补红断言再修复，第二次真实链路三次派出均回指正确的 Run。

## 已知边界

- 全局并发 1 加"未收尾即跳过"：模型轮次很快时，中途审阅常常跨过 Run 结束，Run 结束那次补审被跳过（真实链路 Run 1 即如此），该 Run 最后一段增量要到下一次触发才会被审。
- cli REPL 退出时释放运行面会取消在跑的审阅，退出前最后一次审阅可能以取消收尾。
- 辅助模型 digest 路由、经验覆盖度与自洽性筛查、模型筛查标注的实际产出未做（筛查记录已留可选字段）；"证据已核"状态未落地，M6 状态只走到已扫描或扫描拒收。
- 候选按名字判断取代关系时读暂存目录里的元数据文件，跨种类不判取代。
- 手动补审打开被审会话文件追加记录；若该会话正被另一进程持有，按会话锁响亮失败。
