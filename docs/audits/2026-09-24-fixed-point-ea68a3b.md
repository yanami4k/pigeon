# 定点对照的单步重跑（决策 138、139、151、156、157、164，基线 ea68a3b）

范围：记忆定点对照的事件认定、三组固定挑选、单步重跑、结果行、汇总与断点续跑，以及两个命令。输入为本仓库两条流"去掉记忆"条件一遍整流跑的输出目录。分支 fixed-point，基线为 stream 分支的 ea68a3b（跑批器给每步开工时的树建引用并随流历史导出）。不调用模型接口：用例一律用假模型与在本机执行命令的假 docker。

## 一、施工中定下的口径

| 编号 | 问题 | 做法 |
|---|---|---|
| ① | 容器模式下每步开工时的树（run.started 的 stepStart.baseCommit）原是悬空提交，不在导出的流历史里；缺它时派生会把测试步的红转绿一律判为未知 | 由跑批器在每步开工时建引用 `refs/pigeon/step-start/<流>/<步>`，随流历史导出（stream 的 ea68a3b）。本分支按"流历史里一定有"来写：事件认定与每遍重跑取不到即报错（`StepStartMissingError`），不退回"未知" |
| ② | 回炉时机的记忆在重跑中何时给 | 沿用固定挑选现有语义：回炉组在每一轮回炉都给；事件清单照记原跑中挑到它的轮次。汇总报告开头写明 |
| ③ | 某次验证"题面以外变红"的题面测试文件 | 取 131 修订①的并集，但只用这次验证之前的事实：本步到这次验证为止改动的文件（账本；验证前会被还原的人写受保护测试不算，agent 改过它们也不因此成为题面文件）、开工时已在工作区的文件（开工时的树相对起点提交的差异）、题面直接指到的文件（与派生同一个函数，`mentionedUntracked`）。判不清的记为判不清、不算变红，汇总里单列计数 |
| ④ | 无关记忆的候选与排除 | 候选为事件认定时第 k 步起点派生出、核验通过、与被换条目同一种类（红转绿或撤回）的条目。按整条事实排除：某个指纹只要有任何一条展开的锚点落在排除集里（题面指到的文件、第 k 步改动的文件——人的提交与无记忆跑中 agent 改动的并集——与被换条目涉及的文件），这个指纹下的条目全部不取；与被换条目同指纹的也不取。取成文长度最接近者，平手按编号取最小；同一事件里不重复、不取同指纹的两条。找不到即该事件的无关组缺失、不重跑，汇总列出缺失数 |
| ⑤ | 记忆"被用上"的判定对象 | 只对红转绿条目（带补改文件）判定，撤回类记为不适用（null）；三组都按带记忆组指定的条目与时间窗口算，不带组与无关组即基线 |
| ⑥ | 主判据（决策 164） | 按记忆给出的时机拆开、分开报：开局事件看首轮验证是否题面以外变红；回炉事件只取首轮未过、进入回炉的遍次，看第 1 轮回炉之后的第 2 次验证是否仍题面以外变红，某组没有进入回炉的遍次即该事件在回炉判据上缺失、不补值；两个时机都有的事件两类都计入 |
| ⑦ | 预算 | 与原尝试完全相同，不接受调用方另给；每遍跑完核对到逐项相同 |

按整条事实排除的理由：同一件摩擦按锚点展开成几条同指纹的条目，成文相同，都写着报错文件、变红时已改的文件与补改文件；只看条目自己的锚点，会取到成文里写着本步相关文件的条目。

## 二、事件认定（`src/eval/fixed-point-events.ts`）

对无记忆整流的每一步 k（题与维护步、跑过 agent 的）：

1. 本步会话与此前会话：由跑批器每步完成时写下的会话清单（`sessions-<步>.json`）相减得出；第 k 步的会话恰为一个，此前会话为第 k−1 步完成时的清单。
2. 切流历史：在宿主上把导出的流历史切到第 k−1 步的落地提交，只留它可达的提交（后面各步的提交不进工作区），另带上此前会话 run.started 记下的开工时的树（沿用原引用名；每个的父提交必须是起点或其祖先，否则报错）。
3. 起点：从切片恢复断网容器工作区（恢复时一并取回 step-start 引用），逐个核验开工时的树都在，回到起点提交，写入第 k 步的人写文件，按人的提交切依赖环境——与跑批器每步开工前同一套动作（沿用跑批器已导出的 `syncEnv`）。
4. 挑选：治理根放第 1 到 k−1 步的会话副本，直接调用正式使用的 `createStructuredMemoryPush`（派生、合并、核验同一套代码，工作区经执行端在容器里访问）：开局用第 k 步的题面；再按无记忆跑中第 k 步实际出现的各轮回炉，第 r 轮用第 r 次验证记录里的各步结论调用回炉附加内容。核验对象都是第 k 步起点的代码。推送代码里出现任何"这次不给"的故障即报错，不静默当作没挑到。
5. 任一时机给出至少一条（核验通过）即为事件，记下开局给了哪几条、第几轮回炉给了哪几条，并定下三组的固定挑选：带记忆组给这几条、时机不变；无关组逐条替换（见一节④）；不带组给空。

清单（JSON）另记每个作业结果行的摘要，重跑前核对清单出自同一份整流输出；清单不含时间戳与本机路径，同一输入逐字相同。

## 三、单步重跑（`src/eval/fixed-point-rerun.ts`）

- 作业：事件 × 组 × 遍次（缺省 5 遍、三组），共用跑批器的工作队列，缺省 2 路（可配置，strands 整流跑完后可开到 6）。
- 每遍：新开断网容器，从切片恢复并摆成第 k 步开工时的样子（同事件认定第 3 步）；治理根为这一遍独立的目录（`passes/<事件>/<组>-<遍>`），放第 1 到 k−1 步的会话副本（不带缓存）；按完整条件（回炉 3 轮、撤回、结构化记忆开启）跑完整的一步，记忆的挑选固定为该组的条目（`StepAgentInput.structuredMemoryFixed` 经 Pigeon 步 agent 交给 headless 的 `structuredMemory.fixed`，推送路径与正式使用同一条，不另开注入口）。随后与流中同一口径：规整 agent 的提交、恢复它动过的测试、题跑判题测试、维护步跑验证门，得出最终结论；不落地、不做全量测量。
- 网关与限额：与跑批器同一做法——每遍前等放行、agent 运行时占一路；这一遍期间有限额信号、本作业上游故障或 agent 报被打断即整遍作废：治理根整体移到 `voided/`，从起点重来（与流中作废规则相同，计数上限同跑批器）。轮数与 token 取网关计量，另记网关排队（等空闲账号的累计毫秒）。
- 一致性核对（`replay/fidelity.ts`）：开跑前对每个事件用 `resolveAttemptPlan` 从原尝试（无记忆跑第 k 步会话的首个 Run）解出预算、模型、推理档位、输出上限、温度、工作方式指令、放权方式与工具名单；重跑照搬（`reproducedRuntime`；预算与原尝试完全相同，不接受调用方另给），原尝试的题面须与清单一致、工作方式指令须与跑批器一致。每遍跑完再按重跑自己的 run.started 解出同一组参数逐项核对：预算相同、工具不多（`intersectAttemptTools`）、其余逐项相同，任何一项不符即拒绝、不写结果行。
- 结果行（158：写结果行，不新增账本记录）：事件、流、步、组、遍次、会话；实际给出的条目（取自各 Run 的 run.started：挑选方式、开局、每轮回炉）与它是否和该组指定的一致；首轮验证是否整体不过、是否在题面以外的检查上变红、算作变红的报错、判不清的步；是否进入回炉、第 2 次验证是否在题面以外变红、算作变红的报错、判不清的步；回炉轮数（repair-step 的共用口径）、最后一次验证结论、是否撤回、最终结论；记忆是否被用上及涉及的文件；终态、轮数、token、agent 用时与整遍墙钟、网关（排队、各账号转发数、在途峰值）、限额暂停。
- "题面以外变红"（131 口径，首轮与第 2 次验证同一判法）：格式、类型、分层等非测试步失败一律算；测试步只算题面测试文件以外的用例（题面测试文件见一节③）；测试步或类型未知的步输出无法解析、题面测试文件认定不全、失败清单不全而列出的都属题面，记为判不清。
- 记忆被用上：三组同一口径，按带记忆组指定的红转绿条目，开局条目看首轮验证之前、回炉条目看每一轮回炉（第 r 次验证之后到下一次验证之前），这段时间里 agent 改了条目的补改文件之一即算用上（改动取自账本，与派生同一函数）；不带组与无关组即基线。
- 给出与指定核对：开局逐条相同、每一轮回炉都与指定的回炉条目逐条相同才算一致（用前核验没过而被拦下即不一致）。
- 续跑：结果行按"事件 × 组 × 遍次"成键，同一输出目录重跑只补缺的遍次；进程死在某遍中途留下的治理根在重做前整体移出；追加结果行前，末尾没有换行且解析不了的撕裂行先截掉。同一输出目录加跨进程独占锁（`persistence/exclusive-lock.ts`），撞锁即拒绝并报出占用进程。

## 四、汇总（`src/eval/fixed-point-report.ts`）

`report.md`（决策 164）：总览（事件数及开局、回炉、两者都有的事件数，结果行完成数，无关组缺失的事件数，按时机、按组列出实际给出与指定不一致的遍次作为诊断——开局时机出现不一致即在报告开头醒目提示）；开局判据一节、回炉判据一节（分三行：只在回炉时机挑到记忆的事件、两个时机都有的事件、两者合计），分开算、分开报——可配对事件数、缺失事件数、按事件配对的带记忆减不带变红比例差的均值、帮倒忙的事件数、低于与相同的事件数、无关组对照差均值、判不清的遍次与逐事件表；辅助指标一节三组并列（记忆被用上、平均回炉轮数、最终通过比例），并给带记忆减不带的"用上"比例差。结果行按"事件 × 组 × 遍次"去重（留先写的），只计遍次号不超过遍数的；组别取结果文件里出现的全部组；意向处理，给出与指定不一致的遍次照样进各自判据的分母。变红比例以判得清的遍次为分母。只做描述与配对差，不下显著性结论。

## 五、命令

事件认定（不调模型）：

```
pigeon eval stream-fixed-point-events --manifest <清单> --repo <人的仓库> --image <镜像> \
  --no-memory <无记忆整流的输出目录> --out <事件清单文件> \
  [--streams s1,s2] [--attempt N（缺省 1）] [--container-memory <上限>（缺省 2g）]
```

单步重跑：

```
pigeon eval stream-fixed-point --manifest <清单> --repo <人的仓库> --image <镜像> \
  --no-memory <无记忆整流的输出目录> --events <事件清单> --out <输出目录> \
  [--concurrency N（缺省 2）] [--passes N（缺省 5）] [--groups memory,irrelevant,none] \
  [--model-id <模型>（须与原尝试相同，缺省 kimi-for-coding）] [--container-memory <上限>（缺省 2g）]
```

- 模型账号与 eval stream 相同（`KIMI_API_KEY`、`KIMI_API_KEY_2`… 与各自的并发上限）；预算、推理档位、输出上限、温度不从命令行取，一律照搬原尝试（预算与流中相同，不接受另给）。
- 同一输出目录同一时刻只许一个进程：撞锁即拒绝，报出占用进程与锁文件。
- 输出目录：`results.jsonl`（结果行）、`report.md`（汇总）、`passes/`（各遍治理根）、`voided/`（作废的尝试）、`scratch/`（切流历史的临时目录）。同一输出目录重跑即续跑；有遍次被拒绝或停下时退出码为 3，逐遍列出原因。
- 用法顺序：本仓库两条流的"去掉记忆"整流跑完 → 事件认定 → 单步重跑（先用缺省 2 路；strands 的整流跑完后可 `--concurrency 6`）。

## 七、用例

施工顺序的事实：先写夹具并实跑确认它能产出所需的两条摩擦事实，再写三个模块，随后写用例；用例写成后逐条对照变异反向验证（第八节），承重逻辑均有变异变红。

夹具：人的仓库四步题，用真的 Pigeon（假模型、本机假 docker）跑一遍"去掉记忆"整流：第 1 步改 feature 时误删 core 的标记，core 的测试（题面以外）变红、回炉补改 core 转绿（记忆 F1）；第 2 步给 util 加类型错误、回炉删掉（记忆 F2）；第 3 步题面指到 `src/core.ts`，开局本能挑到 F1；第 4 步又删了 core 的标记，第 1 轮回炉报与 F1 同一指纹、本能挑到 F1。跑批器导出的流历史带 step-start 引用。

## 八、变异反向验证（第一轮，用例名为当时的）

逐个植入、只跑对应的用例文件（端到端的按用例名筛选；夹具照常先跑），记录变红的用例，随即还原；全部跑完后两个源文件逐字核对与植入前相同。不变异时各用例均通过。

| 变异 | 变红的用例 |
|---|---|
| 带记忆组走另一条注入口：记忆编号拼进题面，固定挑选给空 | 三组走结构化记忆的正常推送路径（fixed 选择）……（每遍跑完的一致性核对以"题面不同"拒绝带记忆组与无关组的各遍，用例断言无拒绝而变红） |
