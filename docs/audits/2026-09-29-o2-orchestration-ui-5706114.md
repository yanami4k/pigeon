# 编排二段：编排界面（决策 301）实现审计

- 基线：formal-v2 的 5706114（已含编排一段 o1-orchestration 的合并）
- 分支：o2-orchestration-ui
- 代码提交：13947a9（编排器的只读观察口：worker 的运行事件、流式正文与工具结果）、1e8e309（编排面板取代 worker 状态行、树形视图、进入 worker 会话、状态栏含在跑 worker 的实时花费、命令表）；本审计另起一个提交。
- 范围：决策 301 的五项——精简面板；树形视图（脚本与阶段两层只留节点类型与数据接口）；进入 worker 会话（看、发消息、停止、补批续做、退回主会话）；状态栏本会话花费含在跑 worker 的实时花费；/workers 与面板一致、命令表登记新命令。
- 不做：脚本编排与打转检测；编排器的调度、额度、权限与审批规则不变；eval stream、pigeon run 与逐行对话的行为不变。
- 依据：决策 286、294、297–303。

## 一、编排器的只读观察口（`src/orchestration/workers.ts`、`src/application/workers.ts`）

- 编排器新增 `observe(listener)`：交出各 worker 的活动，三种——运行事件（`event`，轮数记好之后再交出，与 `status()` 一致）、流式正文增量（`delta`，正文与思考）、工具结果（`tool-result`，结果文本与 details），各带 worker 身份（`WorkerRef`）。观察者抛错只进内部故障清单。
- worker 运行面句柄新增两个可选观察口 `subscribeStream`、`subscribeToolResults`，就绪与异步就绪（带 MCP 时）两种句柄都转出运行面已有的同名观察口；异步就绪前的订阅暂存、就绪后接上。
- 只在有观察者时订阅流式正文与工具结果：终端界面在绑定会话时订阅；pigeon run、eval stream 与逐行对话不订阅，行为不变（跑批各条件本来就不派 worker）。两文件的文件头各记一条。
- 补批续做时交给 worker 的那句话抽成 `resumeApprovalText(action)`，文字逐字不变；界面在人另附的话前面同样用它。
- `ChildSessionCosts` 新增只读的 `isCollected(会话号)`（`src/application/session-cost.ts`），界面据此判断某个 worker 的花费是否已由会话记录计入。

## 二、编排面板（`src/tui/worker-panel.ts`）

- 位置：输入框下方，状态栏紧贴输入框，面板在状态栏之下（终端界面一段的状态栏位置不动）。原先输入框上方的 worker 状态行删除，`workerStatusBar` 与旧版 `/workers` 排版 `renderWorkersStatus` 随之删除（已无调用方）。
- 每个 worker 一行，各列以两个空格分隔：名字（按本次列出的最长名字补齐，最多 24）、状态、耗时、轮数（`3t`）、花费、正在做什么。
  - 状态词（ASCII）：queued、running，以及 298 的六种说法 done、failed、timeout（墙钟）、limit（轮数或 token）、cancelled、stalled，另加 blocked（请示被搁下、可补批续做）。
  - 耗时：在跑的为开跑至今，结束的为结构化结果里的耗时，排队的写 `-`；写法 `42s`、`3m05s`、`1h02m`。
  - 花费：本次启动里看到的该 worker 各轮用量与价格（含在跑的），写法同状态栏短写法。
  - 正在做什么：在跑的为最近一个工具调用的一行摘要（与消息区调用行同一写法 `$ 工具名 参数摘要`），还没有调用时写 `starting`；排队的写 `waiting for a free slot`；blocked 写 `needs approval: <动作>`；其余结束的写原因或自述的第一行。
- 过滤（做法照 Claude Code 惯例，行数与时长为本段取的缺省）：列在跑、排队与 blocked 的（按派出先后），其后是淡出期内结束的（新的在前）；最多 5 行，超出的折成一行 `+N more (/workers, ctrl+x)`；结束的 30 秒后淡出，blocked 的要人处理，不淡出；没有要列的 worker 时面板渲染零行。行数上限与淡出时长是壳的选项（`panelMaxRows`、`panelFadeMs`）。
- 刷新：生命周期事件（agent 派、人派与程序派同样）、观察口的每条活动、命令之后都重绘；有在跑或排队的、或还有结束的在淡出期内时，另按 1 秒定时刷新（耗时在走、到点淡出），否则停表。收尾时刻取生命周期事件带的时刻；编排面不发事件时，以壳第一次看到它已收尾的时刻为准。
- 选中（进入面板）：输入框为空时按 ↓ 进入面板，选中第一行，行首出现 `>`，下方多一行按键提示；↑↓ 移动，在第一行再按 ↑ 或按 Esc 回输入框；Enter 进入选中 worker 的会话；x 停止选中的 worker；其余按键离开面板并照常交给输入框。会话选择器打开或审批挂起时 ↓ 不进面板。
- 纯 ASCII chrome；工具参数摘要等内容可含宽字符，按显示宽度截断、不折行。

## 三、树形视图（`src/tui/worker-tree.ts`）

- 切换：Ctrl+X 或 `/agents` 打开，Esc 或 Ctrl+X 关上。Ctrl+X 不在终端界面一段已用的键（Enter、Shift+Enter、Ctrl+J、Alt+Enter、Ctrl+O、Alt+Up、Alt+Q、Esc、Ctrl+C）里，也不在 pi-tui 编辑器的缺省键位里。
- 整屏：视图只有标题、树与状态栏（主会话的消息区、状态行、排队内容与输入框不显示）；切换时强制全量重绘。
- 分层：首行主 agent（会话号）；其下主 agent 或人直接派出的 worker；嵌套派出的 worker 挂在派出它的 worker 之下，缩进一层。脚本与阶段两层的数据接口为 `OrchestrationScriptNode { id, title, state?, phases: OrchestrationPhaseNode[] }` 与 `OrchestrationPhaseNode { id, title, state?, workers: 会话号[] }`，由壳的选项 `scripts` 取数（脚本编排接上）；没有数据时不显示这两层；归在某个阶段下的 worker 只在阶段下列一次。
- worker 节点：`[+]`/`[-]` 加与面板同一排版的一行；缺省收起，展开才在其下列最近 5 条工具调用（已结束的带 `-> ok` 或 `-> error [...]`），还没有调用时写 `(no tool calls yet)`。每个 worker 记最近 20 条调用。
- 任务清单：清单开着时（壳的选项 `taskItems`，入口接当前会话的清单），worker 节点行尾按标签对应标出清单项 `[task #编号 标题 (状态)]`，一个标签对应多项时并列。
- 按键：↑↓ 在 worker 节点间移动（光标在视图关上后保留），→ 展开、← 收起、空格切换，Enter 进入选中 worker 的会话，x 停止它。超出视图高度时以选中行为准取一段显示。

## 四、进入 worker 会话（`src/tui/shell.ts`、`src/tui/message-flow.ts`）

- 入口：面板或树形视图里选中后 Enter。复用已有的会话切换与消息区渲染：运行事件在消息区的投影（轮次标记、工具调用行、工具结果与 diff、Ctrl+O 展开）抽成 `projectRuntimeEvent` 等函数，主会话与 worker 会话共用；进入时新开一个消息区，先按 /resume 同一份历史读取（`loadSessionHistory`，同一上限）写出它会话记录里已有的对话，再接观察口的实时活动（正文与思考流式生长、工具调用、结果）；已收尾的写出收尾摘要。
- 画面：标题换成 `== pigeon tui | worker <名> | session <会话号> | [esc] back to main ==`，状态行写这个 worker 的状态与可用动作（在跑：`[enter] message, /stop, [esc] back`；blocked：`/approve to approve and continue, [enter] continue with a message, [esc] back`；其余结束的：`[enter] continue with a message, [esc] back`）；编排面板与状态栏照常在下方。
- 输入：
  - 在跑或排队的 worker：输入作为消息经编排器的 `send` 递进它的下一轮，送达写"已把话递给 worker X，它在下一轮看到"，未送达如实写出。
  - 已收尾的 worker：输入即让它带着这段话接着做（编排器的 `resume`，不放行任何调用）。
  - `/approve [附言]`：只对 blocked 的 worker，经编排一段的补批续做放行它重新发起的同一个调用（只放行一次）并接着做；带附言时附在补批那句话之后另起一行。
  - `/stop`：走编排器的取消，收尾照常。
  - worker 会话里另可用 `/workers`、`/tasks`、`/agents`、`/quit`；其余命令说明"在 worker 会话里不能用 /x（这里可用 …）；按 Esc 回主会话后再用"，输入留在输入框。
- 退出：Esc 回主会话（标题、消息区与状态行复原）；审批挂起时 Esc 仍归审批面板。
- 主会话照常：主会话的运行、完成通知与排队输入照常进行，其消息区在后台照常更新。主会话的审批（含 worker 汇上来的请求）到来时，若正在 worker 会话、树形视图或面板里，自动回到主会话并写一行"有待审批的调用，已回到主会话"，面板与四键照常。
- `/resume` 换到别的会话时，退出 worker 会话并清掉原会话的 worker 记录。
- 已知限制：进入时某条回复正在流式输出的，只显示进入之后的部分（这条回复写进会话记录之前不在历史里）。

## 五、状态栏的本会话花费（`src/tui/worker-activity.ts`、`src/tui/shell.ts`）

- 面板、树形视图与状态栏读同一份 worker 活动记录（观察口的轮次收尾用量），同源。
- 本会话花费 = 原有部分（续接的已有花费、主 agent 各轮、工具另发的请求、会话记录计入的已收尾子会话）+ 在跑 worker 的实时花费。每轮收尾即刷新，不再等 worker 收尾。
- worker 收尾后照旧由会话记录计入（决策 286 的规则不变）；计入之后该 worker 的实时部分清零，不重复计；此后补批续做的新花费照常实时累计。没有会话根（替身运行面）时只有实时部分。
- 实时计价的模型接入取主会话的（DeepSeek 回复自带价格为 0 时按官方人民币价目计）；角色覆盖了模型接入的 worker，收尾后以会话记录为准。

## 六、命令

- `/workers` 保留：每个 worker 一行与面板那一行逐字相同，列全部 worker（不过滤、不淡出、不设上限），下一行写角色、分支与会话号；没有 worker 时文字不变。
- 命令表（`src/tui/command-table.ts`）新增三条，都是运行中可用：`/agents`（切换树形视图，有编排面且不在沙箱时可用）、`/stop`、`/approve [附言]`（只在 worker 会话里可用；主会话里输入时说明怎么进入 worker 会话）。命令表新增"worker 会话里能不能用"一栏（`inWorkerSession`），标了的为 /quit、/workers、/agents、/stop、/approve、/tasks。运行中放行表相应为 quit、sessions、search、grants、cancel、workers、agents、stop、approve、tasks。
- 编排面（`TuiWorkersFace`）新增可选 `observe`、`send`、`resume`，`subscribe` 的监听器带上生命周期事件；终端界面入口把它们接到编排器。

## 九、上手试用清单（本机 Windows Terminal）

虚拟屏测不到真实终端的按键差异，以下每项一行：怎么试 → 应看到什么。

1. 让主 agent 派 2 个 worker → 输入框下方、状态栏之下每个 worker 一行：名字、running、耗时每秒在走、轮数与花费随每轮增加、末列是最近一个工具调用。
2. 用 `/spawn explorer "看看目录结构"` 派一个 → 同样多出一行。
3. 让 agent 一次派 6 个以上 → 只列 5 行，末行 `+N more (/workers, ctrl+x)`。
4. 等一个 worker 结束 → 那一行变 done、末列是它自述的第一行，约 30 秒后消失；全部消失后状态栏回到最后一行，下方不留空行。
5. 输入框为空时按 ↓ → 第一行前出现 `>`、下方一行按键提示；↑↓ 移动；在第一行按 ↑ 或按 Esc 回输入框；在面板里直接打字 → 回到输入框且字进了输入框。
6. 面板里选中一个按 Enter → 标题变成 `worker <名> | session …`，消息区是它已有的对话，之后实时滚动。
7. 在 worker 会话里输入一段话回车 → 出现"已把话递给 worker …"，它下一轮的回复提到这段话。
8. 在 worker 会话里输入 `/stop` → 出现 `[cancel] ...` 与收尾摘要"已取消"。
9. 按 Esc → 回到主会话，消息区是主会话的内容，期间主 agent 的输出都在。
10. 按 Ctrl+X → 整屏树形视图；若没有反应，记下终端是否截走了 Ctrl+X；输入 `/agents` 同样打开。
11. 树里 ↑↓ 移动、→ 或空格展开 → 该 worker 下列出最近 5 条工具调用；← 收起；Enter 进入它的会话；x 停止它；Esc 关闭。
12. 开着任务清单，让 agent 用 update_tasks 给某项写 worker_label，再派同一标签的 worker → 树里该 worker 行尾出现 `[task #n 标题 (状态)]`。
13. 把 `.pigeon/orchestration.json` 的 approvalTimeoutMinutes 设为 1，让 tester 跑一个未登记的命令并且不理审批面板 → 约 1 分钟后面板撤下，该 worker 行显示 blocked 与 `needs approval: 跑命令 …`，且不淡出；进入它的会话输入 `/approve` → 它重新跑那条命令（不再弹审批）并接着做完。
14. 在 worker 会话或树形视图里时让主 agent 发起一次审批 → 自动回到主会话，出现"有待审批的调用，已回到主会话"与审批面板，y/n 照常。
15. worker 在跑时看状态栏的 cost → 随 worker 每一轮增加，不等它收尾；它收尾后数值不跳变。
16. 把窗口拖窄到 40 列左右 → 面板每个 worker 仍是一行（截断不折行），树形视图与 worker 会话不错位；拖宽后恢复。
17. 在 worker 会话里按 Ctrl+O → 展开或收起它的工具结果；回到主会话后展开状态一致。
18. 输入 `/workers` → 每个 worker 一行与面板一致，下一行写角色、分支与会话号。
