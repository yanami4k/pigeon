## 八、发现的问题

1. **分析脚本报告的 session 汇总被同摘要目录覆盖（分析缺陷，只影响显示）**
   - 现象：一次读入两个目录时，校准报告"输入"一节显示"0 个作业、0 个 session 文件"；只读两格目录时为 4 个作业、90 个 session 文件。
   - 原因：`reader.load_table` 以身份摘要为键记录 session 汇总（`sessions_info[digest] = info`），两个目录摘要相同，后读的最简 agent 目录覆盖了前者。各步的 session 计数按目录分别合并（`session_counts`），不受影响；5.1 至 5.7 不用 session 数据。
   - 复现：分析脚本一次读入摘要相同、分别只含 Pigeon 条件与只含 minimal 的两个输出目录，看 `result.json` 的 `input.sessions`。
2. **`calibration --eligible` 的编号空间（用法说明不清）**：参数说明写"要做到的不为零的全部题号"，而核对比较的是结果行的步序（`seq`）。给 1 至 89 的题号时核对显示"否"，给这 89 道题的步序时为"是"。分析脚本内部的"题号"即步序（`reader.read_baseline_failures` 也按步序换算），正式分析给 `--tasks` 时同样应给步序。
3. **判题前查 pytest 配置时 git 报错打到日志（记录）**：每步日志有一行 `fatal: path 'strands-py/pytest.ini' does not exist in <提交>`，来自 `src/eval/stream-profiles.ts` 按顺序查找人的树里 pytest 配置文件的探测，找不到即换下一个，不影响判题。
