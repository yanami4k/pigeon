# 撤回拆除（决策 172、173，基线 455d88d）

范围：从代码中删去"回炉修满或预算耗尽仍不过即回退"的一整支。回炉修满或预算用尽、验证仍不过时，这一步以失败收尾，工作区保留 agent 的改动，不做任何回退；失败由既有的验证记录体现。"不过门不合入"以后作为独立的合入环节考虑，不在编码 agent 里做。基线为 fixed-point 分支头 455d88d（含 5275ca2 与定点对照的全部提交），分支 formal-v2。

## 一、施工中定下的口径

1. 流里与定点重跑的本步 `outcome` 只看判题：题跑判题测试，维护步跑验证门，判的是落地的 agent 代码。回炉的最终结论另记在 `finalVerdict`。"回炉最终为 fail 而判题全过"记为 passed。主判据怎样组合这些字段另行裁决，这里只定单字段口径。
2. 失败归因删去"缺前置"的判定。它的前提是撤回（142），已由 172 取代。新行不再出现这一归因，旧行照常显示标签。
3. 报告次要指标表的"撤回"列只在结果里带 `reverted` 字段时出现：旧结果照旧，新结果不显示。
4. "本地开启回炉须是 git 工作区"的要求保留，行为不变，只改报错文案；理由从"撤回要按快照恢复"改为"回炉要按快照记下这一步的起点与改动"。结构化记忆已裁决停止（174），整块删除时这条要求的理由会再变，届时重审。
5. 开工忽略清单（154 修订 ③）除撤回外没有读者，本轮一并删除（见第三节）。
6. 结构化记忆因 174 已停，只做能编译、行为正确所需的最小改动。

## 三、留了什么及原因

| 保留 | 被谁用 |

| `repairRoundsOf`、`stepRunsOf`、`lastStepRunOf`、`lastGateVerificationOf`、`repairStepOutcome` 的 `rounds` 与 `verdict` | 成败标签、结构化记忆、定点对照 |

开工忽略清单与 170（记忆把被 git 忽略的文件当代码改动）的关系：170 的来源是 `run_command` 回执的文件变化（执行端全量列文件，含 `__pycache__` 等被忽略文件），经 `ledgerFileChanges` 进入"改动文件"。开工忽略清单只记开工时已被忽略的路径，这一步里新生成的被忽略文件恰恰不在其中；容器一侧的清单只在内存里、不入账本，派生时取不到。170 需要的是派生时按忽略规则现查，与这份清单无关。清单除撤回外无人读，因此删除，不留只写不读的记录。

## 四、只读兼容

- 结果行 `StreamResultLine`：`reverted`、`repairBudgetExhausted` 改为可选；新行不写。`STREAM_RESULT_FIELDS` 只列新行写的字段，另设 `LEGACY_STREAM_RESULT_FIELDS` 列旧行才带的两个。读取仍是逐行 `JSON.parse`，不拒收带这些字段的旧行。
- 评测结果行 `EvalResultLine.repair`：`reverted`、`budgetExhausted`、`restored`、`restoreError` 改为可选，新行不写。
- 定点对照结果行的 `reverted`、试跑行的 `reverted` 与 `budgetExhausted` 改为可选，新行不写。
- `FailureAttribution` 的类型与标签保留 `missing-prerequisite`，旧行照常显示"缺前置"。
- 定点对照冻结事件里 `MemoryItem.kind` 保留 `"reverted"`，旧事件文件照常可读。
- 旧账本照旧可读、不做迁移。撤回从未单独入账，只靠推断。

## 五、已接受的后果

- 旧会话不再显示为"已撤回"：推断已删，回炉开启且最后一次验证失败的旧会话现在只表现为"这一步以失败收尾"。成败标签不变（仍为失败）。
- 旧会话里被撤回的尝试不再派生为记忆事实；规则标记推进后缓存整份重算，此前缓存里的撤回类条目随之消失。
- 流里修不好的代码照样落地，后续各步在它之上接着做；被撤回步的测试以前在全量测量里一律算失败，现在按落地代码的实际结果计。

## 七、回看原来按撤回推断查证的断言

逐个检查被改写的断言，确认没有变成恒真的空转断言：

- 原"快照范围内与第一个 Run 之前逐字一致"（`scopeState` 与开工前相等）一类断言全部改为对具体内容的断言（`a.txt` 为哪一版、哪些文件在），不会因为什么都没发生而通过；变异一（恢复回退）使它们变红。
- 记忆的"不产出撤回类事实"两例：派生结果为空本身可能因为会话没开回炉或没有验证记录而恒真，所以先断言会话形状（回炉开启、最后一次验证为 fail、`repairStepOutcome` 为 `{ rounds, verdict: "fail" }`）；变异二（重新产出撤回类事实）使两例变红。
- 流里"各行不带撤回字段"的循环：若结果为空即空转，同一用例另断言第 1、2 步的具体取值，结果非空；变异一（跑批器一侧）使该用例变红。
- 报告"新结果不显示撤回列"：若表格整个没生成即空转，同一用例另有对表头 `| 条件 | 判定通过 | 回归 |` 的正向断言。
- `stream-agents.test.ts` 里"覆盖人写测试的 conftest"一例原断言 `a.txt` 仍为 `bug`：这一例里 agent 从不改 `a.txt`，撤回与否这条断言都成立，是空转断言，已删去，只保留回炉轮数与结论。
- 崩溃窗口一例原断言"推为未撤回"，改为断言 `repairStepOutcome` 严格等于 `{ rounds: 1 }`（没有结论），并保留截断后验证记录只剩首个 Run 一条、标签为未知的断言。
