# 记忆文件的落盘格式改英文与旧文件一次性迁移（决策 431）审计

基线 12bc700。提交：cf20d0e（代码与测试）、7f9738c（文档），并入集成线的合并提交 aaf381c。

## 一、改了什么

- 新格式（`src/memory/learned.ts`）：条目一行一条 `- [P3] 内容 (recorded 2026-10-01 · tui · session sess_…)`，来源为英文短名（终端界面 tui、命令行对话 cli）；两层文件头为英文（标题 `# Learned memory (this project)` / `# Learned memory (all projects)` 加一行注释）。尾巴按行末最后一段取，内容不再替换括号；内容本身以形如尾巴的文字结尾时，读回与写回逐字不变。推送给模型的记忆文字版本 v4 → v5。
- 一次性迁移（新增 `src/memory/memory-migration.ts`，旧格式只在这里认读）：
  - 判定为旧格式：文件头里有旧标题行或旧注释行，或条目区任何一行以旧尾巴（〔日期 · 来源 · 会话 …〕）结尾。
  - 触发：推送记忆的每次读取（开局、每个 Run 开始、update_memory 之后）、`/memory` 查看、`/memory edit` 打开与保存、update_memory 写入。
  - 做法：在记忆锁里现读原文，先把原文按字节复制进迁移备份目录，再原子写整份改写成新格式，并给人报一行备份位置。备份或改写出错即不写。已是新格式的文件不碰、不备份，转换幂等。
  - 转换：只换旧标题行与旧注释行，人加的其他文件头行原样；来源"终端界面"→ tui、"命令行对话"→ cli，认不出的来源原样；编号、内容、日期、会话号不变；没有尾巴的条目照旧没有尾巴；CRLF 规范为 LF。
  - 拿不到锁或出错（读路径）：这一次在内存里转换后照常读出、文件不动，给人留一行告警，下次读到时再试。update_memory 与 `/memory edit` 保存已持锁，出错即不写（前者报错，后者回"没有保存"）。
  - 备份位置：项目级在使用者目录下 `.pigeon/state/migration-backup/<项目名>-<哈希>/state/memory.md`，用户级在同目录的 `user/state/memory.md`；同名备份内容相同即沿用，不同则另取 `memory.1.md` 等。
- 文档：`docs/configuration.md` 记忆一节写明新格式与一次性迁移。
