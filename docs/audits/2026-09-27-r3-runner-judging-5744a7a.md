# 跑批器二：两类用例、部分得分与校准能力（决策 196、201、202、213、214、218、219、223、225；146、171、198、200 修订，基线 5744a7a）

范围：为每道题算两类用例的基线（214）并按提交缓存，提供可续算、可并发的预计算命令；判题改为放入人的测试后跑一次全量、按两类用例计分（196、201）；接上给用例名的题面（213）；报告按新计分重做（146、201）；校准所需的选题、按条件子集续跑与结果行新字段（202、219、225）；流水线只做预开下一步的容器。基线为 runner-r2 分支的 5744a7a（其后一次只改审计措辞的提交 503018d），分支 runner-r3。网关、计价与上限、最简 agent、会话存储、推送记忆与复盘本身、统计分析脚本不在本段。

## 一、两类用例（214）

### 算法

对清单里的每道题（题按时间接成一条流，共 89 道）：

- 之后一侧：人该步的代码（step.commit）上跑人在该步的全部测试两遍，即原有的人的基准（`<commit>.json`），逐条比对得每遍都通过的与时过时不过的用例。
- 之前一侧（叠放运行）：参考工作区检出人在该步之前的代码（step.parent），叠上人在该步的测试、测试辅助与环境文件（红测试对取合并后 step.commit 上的版本），依赖按叠上的人的声明切换，pytest 配置显式取 step.commit 的版本（不读工作区里 parent 的），跑同一批测试两遍。只跑 pytest，ruff 与 mypy 的配置不进这一步。
- 判定（纯函数 `classifyCases`）：
  - 要做到的：之后两遍都通过，之前两遍都没通过（失败、跳过、缺席都算没通过；parent 侧收集失败时该文件的用例整个缺席，按没通过算）。
  - 不许挂的：四遍都通过。
  - 时过时不过：任一侧两遍结果不同（通过、失败、跳过、缺席任一不同，与人的基准同一口径）的，两类都不进，单独计数。
  - 其余（之后没通过，即人自己弄坏或删掉的）两类都不进；收集失败的伪用例（`文件::<collection>`）不进任何一类。
- 叠放运行拿不全用例的结果（报告写不出且续跑没有进展）即报错，这道题记为出错：缺席会被当作没通过，整遍缺失会把不许挂的误判成要做到的。
- 要做到的里不在本题测试文件（人在该步新写或改过的测试文件）中的条数另记为 `failToPassOutsideJudgeFiles`。

### 缓存格式（基准目录下，按提交）

| 文件 | 内容 |
|---|---|
| `<commit>.json` | 之后一侧（原有人的基准，格式不变） |
| `<commit>.overlay.json` | 之前一侧：`cases`、`passing`、`flaky`、`runs`（每遍内存峰值、上限、墙钟）、`slowest`、`stuck`、`parent`（叠放的起点）、`overlay`（叠上的文件，形如 `write 路径`）、`identity`（镜像 ID 与跑用例外壳的摘要） |
| `<commit>.classes.json` | 由两份现算的两类：`seq`、`commit`、`parent`、`failToPass`、`passToPass`、`excludedFlaky`（均为用例编号）、`failToPassOutsideJudgeFiles`；只供事后读，不作缓存 |
| `classes-summary.json` | 预计算命令的汇总：每道题（题号、步序、提交、起点）两类的条数、排除数，出错的题与原因 |

叠放结果读回的条件：身份相符（或按既有等价表读回，且没有挂起迹象），且记下的 `parent` 就是这一步的 parent；否则重算。

### 预计算命令

`pigeon eval stream-baseline --manifest <清单> --repo <人的仓库> --image <镜像> --out <基准目录> --check classes [--concurrency N]`：每路一个参考容器，按题分摊；两侧各按提交落盘，同一目录重跑即续算；一道题出错记下、接着算其余的；结束写 `classes-summary.json`，并打印要做到的为零的题号。正式跑与校准的 `eval stream --baseline <基准目录>` 读同一目录；没预计算的题在跑批时现算。

## 二、判题与计分（196、201）

- 判题前的恢复与清理不变（恢复 agent 动过的测试、写入人在该步的测试、195 的判题前清理、按人的声明切环境）。原"本题测试子集判题 + 全量测量"合并为一次：工作区的测试与测试辅助文件同步成人在该步的全部（agent 新建的删掉，与原全量测量同一口径），跑人在该步的全部测试一次，再跑静态检查计数。
- 计分（纯函数 `judgeStep`）：每步得分 = 要做到的里通过的比例；做成 = 要做到的全过且不许挂的无一失败；不许挂的一类记失败条数。没有结果的用例（缺席、收集失败、整次运行被杀）算没通过。要做到的为零的步照跑，得分与做成记空，不进主判据分母。
- `outcome`：要做到的全过（为零时即成立）且不许挂的无一失败记 passed，否则 failed；主判据看 `judging`。
- 两类用例在每步开工前取得（题面给用例名时要用），结果不进 agent 可见的任何地方。

## 三、题面给用例名（213）

`--prompt-format test-cases` 接上：名单为这一步要做到的用例编号，不附内容；缺省仍给测试文件路径。原"没接上即拒绝开跑"的检查删除。

## 四、结果行字段

新行写的字段（旧结果行照常读出，`fullPassRate`、`head`、`regressions`、`attribution`、`reverted`、`repairBudgetExhausted` 列为只读兼容的旧字段）：

| 字段 | 含义 |
|---|---|
| `start` | 起点，即 step.parent |
| `judging.failToPass.passed` / `.total` | 要做到的通过数与总数 |
| `judging.score` | 每步得分；要做到的为零时为 null |
| `judging.passToPass.failed` / `.total` | 不许挂的失败数与总数 |
| `judging.solved` | 做成与否；要做到的为零时为 null |
| `judging.failedCases.failToPass` / `.passToPass` / `.truncated` | 没通过的用例编号，每类最多 20 条 |
| `judging.excludedFlaky` | 因时过时不过排除的用例数 |
| `gateway.costCny` | 本步 agent 的花费（元）：网关计量的 `costCny` 按步做差 |
| `gateway.reviewCostCny` | 本步复盘的花费（元）；复盘接入之前为 null |
| `gateway.peakInputTokens` | 本步单次请求输入 token 峰值：网关计量的 `peakInputTokens`（每步开始时重记） |
| `memoryAtStart.bytes` / `.entries` / `.entryChars` | 开工时（快照取定或恢复之后）MEMORY.md 的字节数、条目数（以 `- [L编号]` 开头的行）、条目部分的字符数（从第一条起按 Unicode 码点计，文件头不计）；文件不在记 0 |
| `memoryAtEnd`（同上三项） | agent 运行与收尾复盘结束之后（判题之前）的记忆大小；最后一步的即一遍结束时的值 |
| `hitStepBudget` | 是否撞宽上限：终态为 turn-limit 或 wall-clock-limit，或轮数、墙钟（含验证门与回炉）达到上限 |
| `hitReviewBudget` | 复盘是否撞复盘上限；复盘接入之前为 null |
| `review.turns` / `.wallMs` | 复盘的轮数与墙钟；复盘接入之前 `review` 为 null |
| `turns` / `agentWallMs` | 每步轮数与 agent 墙钟（含验证门与回炉） |
| `envOpenMs` / `envPrefetched` | 取到容器的等待毫秒；容器是否在上一步进行时预先开好 |

花费与峰值的读取点：跑批器在一步前后各读一次网关计量（`meter(job)`），`costCny` 取两者之差、`peakInputTokens` 取收尾时的值；本分支的网关计量没有这两项，读到的即为 null，接入网关计价后按同名字段接上，不改网关与计价模块。

分析脚本读入层暂用名与本实现的对应：targetPassed / targetTotal / targetScore → `judging.failToPass.passed` / `.total` / `judging.score`；solved → `judging.solved`；keepFailed / keepTotal → `judging.passToPass.failed` / `.total`；flakyExcluded → `judging.excludedFlaky`；stepCost → `gateway.costCny`；reviewCost → `gateway.reviewCostCny`；reviewTurns / reviewWallMs → `review.turns` / `.wallMs`；peakInputTokens → `gateway.peakInputTokens`；memoryBytes / memoryChars / memoryEntries → `memoryAtStart` 或 `memoryAtEnd` 的 `bytes` / `entryChars` / `entries`；hitStepBudget / hitReviewBudget 同名。

## 五、报告（146、201）

- 每步得分表：各格各遍在已判的步上取每步得分的等权平均，合并与分段各一列（分段为清单里按重置点切出的各段，固定起点下只用于分段报告）；另列做成步数、不许挂的失败合计、要做到的为零的步数、已判步数。多遍时另给各遍等权的均值与范围。
- 同题两遍的每步得分差：同一格第 1、2 遍都有得分的步逐步相减，给平均差、平均绝对差与样本方差，只作描述。
- 每步用量：轮数、agent 墙钟、花费、上下文峰值、开工时记忆条目字符与条目数、复盘轮数、墙钟与花费的中位、90 分位（最近秩）与最大，撞宽上限的步数与撞复盘上限的次数。
- 每步明细（第一遍）与次要指标（静态检查各步合计、token、墙钟、限额暂停、依赖环境选不出而作废的步）。
- 跑批器一留下的终点值与补跑提示（延续式口径）删除：终点在固定起点下只是最后一题的得分，第 3 遍按 224 由分析脚本判定。统计检验不在代码里做。
- 旧口径的结果行只报条数，不计入各表。

## 六、校准能力（202、219、225）

- 选题：`eval stream --tasks 题号,…` 按题号（清单里的题按时间接成的流中的序号，从 1 起）；`--sample K [--seed N]` 只在要做到的不为零的题里，按 Python 的 `random.Random(seed).sample` 抽 K 道再按时间排序，缺省种子 20260927。抽样要求全部题的两类用例已预计算，缺了即在写身份头之前拒绝并列出题号；两者只能二选一；题号越界或重复即拒绝。
- 抽样由 TypeScript 实现的梅森旋转与 CPython 的 `sample` 两种分支逐位一致（对照值由 CPython 3.13 算出，含 89 道里抽 15 道：`[31, 63, 41, 16, 10, 64, 52, 47, 88, 14, 40, 24, 86, 60, 38]`，按时间排序后即题单）。
- 身份头 core 新增 `taskSelection`（`all`、`list` 带题号、`sample` 带种子、样本数、总体说明与抽出的题号）。
- 按条件子集续跑：条件与各 agent 的参数不整体比对——条件取并集写回，某个 agent 两次都记了参数才逐项比对，只有一边记了即补上；摘要不含这两项，子集续跑时不变。其余各项（含选题）照旧逐项比对。同一份题单整份跑第二遍用 `--attempts 2`（遍次各自一个治理根，各从空记忆开始），最简 agent 以 `--conditions minimal` 在同一输出目录跑。
- 宽上限以参数给出：`--max-turns 300 --wall-clock-min 60`（含验证门与回炉，复盘另算）。

## 七、流水线的取舍

只做预开下一步的容器：当前步取到容器后、agent 开始之前即为下一步新开容器，下一步开工时直接取用（取用失败则现开）；同一作业至多两个容器，按步在题单中的位置轮流用两个槽位命名；作业结束或停下时预开的容器一律丢弃。

判分与下一步开工重叠未做：重叠后同一作业同时有判分与 agent 两个在途阶段，结果行须按步序写而判分可能晚于下一步完成，崩溃续跑、作废重做与停止信号的时序都要重新设计与测试，复杂度与测试难度明显增加。收尾复盘的接入点留在 agent 结束之后、判题之前（步末记忆大小在此记），"复盘结束才算这一步的 agent 部分结束"在顺序执行下自然成立。

## 八、实跑验收

在验证服务器上跑（8 vCPU、31 GB；strands v6 镜像由备份载入，14 层的层摘要与本机所用镜像逐字一致），代码为 e38b2db。取 89 道题中的题 1、2、20（步序 3、8、68；题 20 叠放了依赖声明的改动），之后一侧读已落盘的人的基准（按既有镜像与外壳等价表读回），之前一侧现算，参考容器 1 个、内存上限 2 GB。

|---|---|---|---|---|---|---|---|
| 1 | 3 | 16 | 5470 | 0 | 0 | 2.0 分、722 MiB；1.9 分、720 MiB | 3.9 分 |

## 九、测试与改写的断言

新增 stream-classes、stream-sample 两个测试文件；stream-runner、stream-report、stream-results、stream-identity、stream-experiment、stream-memory-snapshot 的测试按新计分改写。改写时逐个回看的断言：

- 原"第 1 步全量测量 3/3（篡改的 keep 测试已还原）"：agent 原先把 keep 改成 `exit 0`，还原与否都通过，断言恒真；改为把 keep 改成 `exit 1`，没还原即不许挂的失败 1 条，断言查 `passToPass.failed = 0`。
- 原"判题与测量两处调用"的区分（按测试清单是否含 keep）：判题只剩一次全量，改为断言每步恰好一次全量运行，避免"某次调用满足条件"式的空转。
- 原"全量测量被杀、分母仍在人这一侧"：原写法在 parent 上同样会杀掉外壳，叠放运行拿不全即报错；改为只在 agent 写错时杀外壳，断言要做到的 0/2、不许挂的失败 1/1 与失败编号。
- 原"agent 自己测试的辅助文件判题时都在"：单次全量运行前按人在该步的测试同步，语义反转为"跟踪得到的不在"，作业照常不停。
- 原"停止信号在判题或测量期间到达"：改为判题的全量运行期间与其后的静态检查期间两处。
- 原"停止时在途容器丢弃、排队作业不开容器"：预开后多一个容器，断言改为两个都丢弃、排队的作业一个都不开。
- 原"网关计量取差"：计量加入花费与输入峰值，断言作废过的一步只计重做那次的花费、峰值每步重记。
