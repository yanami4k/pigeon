范围：按 docs/roadmap/comparative-eval-analysis-plan.md（预注册，入库提交 1720f75）在 `eval/analysis` 里实现两组对比的分析与试跑取值规则，在试跑数据上演练。只改 `eval/analysis`；`src/`、决策索引、路线图与预注册文件无改动；冻结标签 formal-run-v1 未动。两组的条件名由命令行给：`--group-a` 为 Pigeon 组（P），`--group-b` 为对照组（D，外部 agent 条件）。

## 一、实现与预注册各节的对应

### 既有模块的改动（行为不变）

- `reader.py`：从 `row_to_record` 拆出 `record_for_cell`（按调用方给的格子转记录、缺字段即报错），`row_to_record` 照旧先认条件名再调它。
- `primary.py`：`select_tasks` 加 `cells` 参数，缺省为四格，取值与原来相同。
- `constants.py`：追加对比评测一节的常数，原有常数不动。上一轮的 2×2 分析、校准、敏感性分析的代码路径与种子不变，原有测试照旧通过（见第二节）。

### 第 1 节 每一步的计量

- 读结果行里的两类用例计数与部分得分，与上一轮同一套映射（`FIELD_MAP`）；要做到的为空的步得分记空、单列；无法建立基线的步排除并单列。
- 作废重做：跑批器不写作废的行。作废次数取作业目录里 agent 每次运行开的尝试目录（Pigeon 组 `pigeon-docker/step-<步序>/try-<n>`，外部 agent 条件 `external/step-<步序>/try-<n>`）：有结果行的步为尝试数减一，没有结果行的步各次尝试都算作废。
- 缺失：所给全部步（`--tasks`；不给即结果行里出现的步）× 两组出现过的遍次里没有结果行的，或有行而没判分的（不含无法建立基线），列为最终缺失。

### 第 2 节 主判据（`comparative.py` 的 `comparative_primary`）

- 2.1：各组各题先对已有效的各遍等权平均（`cell_task_means`，缺一遍即按另一遍），d(i) = ȳ(P, i) − ȳ(D, i)，Δ 为有效题上的等权平均。
- 2.2：有效题 = 要做到的不为空、能建立基线、两组各至少一遍有效结果；缺失题列出步号与哪一组无结果；缺失题超过有效题的 10%（不含端点）即 `exploratory`，报告置顶注明降格为探索性。
- 2.3：按题配对的符号翻转检验 100,000 次、双侧，p = (次数 + 1) ÷ (翻转次数 + 1)，p ≤ 0.05 判显著；按题自助法 10,000 次取 2.5% 与 97.5% 分位；种子写在 `constants.py`（置换 202610071、自助法 202610072，与上一轮的种子分开）。稳健性对照为 `score ~ arm + (1|题) + (1|作业)`，arm 按 P = +0.5、D = −0.5 编码（系数即 P − D），作业 = 组 × 遍；方向或显著性与主检验不一致即注明"结论对建模方式敏感"；拟合失败或未收敛时注明，不作比较，主结论照主检验。dz = mean(d) ÷ sd(d)；相对差 = Δ ÷（有效题上 ȳ(D, i) 的平均）。
- 2.4：M = 2.80 × sd(d) ÷ √n，sd 取样本标准差，用本次数据。

### 第 3 节 次要判据（全部标探索性，p 不校正）

- 做成与否：有效题上两组做成率；配对差按 2.1 的方法给估计、自助法区间与 p。
- 不许挂一类的失败：每组合计、每步平均、有失败的步数（全部有结果的步）；每步失败数的配对差同上。
- 随题推进：d(i) 对时间位置 t(i)（全部步按时间，第一步 0、最后一步 1）的最小二乘斜率与其自助法区间；后半段差为后一半有效题减前一半（奇数去掉正中一题），复用 `secondary.py` 的 `_slope`、`half_difference`、`time_positions`。
- 花费与效率：每步非高峰折算花费、实付花费（参照）、输入 token 未命中与命中、输出 token、墙钟、请求数，两组中位数与 90 分位，有效题上按题配对差的中位数；另报两组合计。非高峰折算：网关逐请求计价、高峰整条翻倍，非高峰价对用量是线性的，每步折算花费 = 该步用量合计 × 非高峰价目（`constants.py` 的价目与 `src/state/model-pricing.ts` 一致）。
- 撞上限与作废：两组都不限轮数（398），撞每步上限只看墙钟——终态 `wall-clock-limit` 或 agent 用时达到身份头的墙钟上限；结果行 `hitStepBudget` 为真的步（它把请求数达到身份头的 `maxTurns` 也算作撞上限）只并列作参照。另报以轮数上限收尾的步、作废重做次数、最终缺失的步。
- Pigeon 的机制使用（只描述）：取自 Pigeon 组作业治理根里的会话文件，按每步会话清单之差归到步——`search_sessions`、`read_session_entry`、`list_sessions` 调用次数，检索命中的会话数（结果里会话号去重，兼容按会话归并前后两种结果），派出的 worker 数、其中建工作树的数、角色与收尾状态，上下文裁剪（`pigeon.prune`）、压缩（`compaction` 条目）与截断续跑（`pigeon.continuation`）次数；主会话与 worker 会话合计。没有会话根的作业整组记为"未记录"。

### 第 4 节 固定措辞（`comparative_report.py`）

- 四种句式：显著且 Δ > 0、显著且 Δ < 0、不显著且区间两端都在 ±M 以内（"两组相当"）、不显著且区间超出（"未测出两组的差别……不能排除约 M 个百分点以上的差距"）。显著与否先于区间判断。
- 两组有效题上的平均部分得分都 ≥ 90% 时结论后加"（两组都接近满分）"；建模敏感按 2.3 加注；缺失超过 10% 置顶降格。
- 花费单独一句：两组每步非高峰折算花费的中位数与 90 分位、按题配对差的中位数，不与得分合并。

### 第 5 节 试跑取值规则（`comparative_pilot.py`、`comparative_sources.py`）

- 5.1：报身份头的选题；给 `--eligible`（要做到的不为空的步）时按 `random.Random(20261007).sample` 抽 8 道核对。
- 5.2：cP、cD 为两组每步平均的非高峰折算花费（留下结果行的那次），C = 79 × (cP + cD) × 2 × 1.2；另报实付、按高峰价计的步、实付不在折算 1–2 倍之间（价目对不上）的步、各目录网关累计（含作废与探测）。控制台账单核对不在脚本内，报告写明须另行核对。
- 5.3：核对身份头每步墙钟为 60 分钟；列出撞墙钟上限的步供看轨迹，有则写明"先诊断打转还是做不完，做不完则正式跑上调到 120 分钟并在报告里注明"，没有则维持 60 分钟；另列仅因请求数达到身份头轮数而被结果行标为撞上限的步。
- 5.4：网关留存——有网关计量的步都有留存、每题体积（各次尝试合计）与 0.8–1.6 MiB 估算比并列出不符的步、作业共用 blobs 体积、存全量与截断的请求、截断的回复、回复状态、多轮请求（消息多于一条）的 400、回复里思考块签名为空的个数（SSE 的 `content_block_start` 与 `signature_delta` 拼合；非流式取正文）、请求里回传的思考块签名为空的个数、请求头里名字像鉴权的项。不读、不核对任何 key。worker：派出数、角色与收尾状态。工作树占盘：k = Pigeon 组每题派出的建工作树的 worker 平均数，推算 k × 33 MB × 79 × 2 × 1.5（MB、GB 按十进制），给 `--free-gb` 时与剩余空间减 5 GB 比较，超过即写明按决策 399 改为判完一题即删该题的工作树；另报作业目录里实有的工作树个数。高峰暂停：读输出目录的 `peak-pauses.jsonl`，没有暂停即写明"未覆盖"。
- 试跑报告不算、不写两组得分之差。

### 第 6 节

- 两个子命令：`comparative`（第 1–4 节）与 `comparative-pilot`（第 5 节），各在输出目录写 `report.md` 与 `result.json`；同一输入两次运行逐字相同。`eval/analysis/README.md` 补"对比评测（两组）"一节。冻结提交号待演练完成、正式跑开始前记下。

## 四、预注册里的歧义（只列问题与选项）

1. 5.3"结果行记每步是否撞上限"：结果行的 `hitStepBudget` 把请求数达到身份头 `maxTurns`（试跑为 150）也算撞上限，而 398 定两组都不限轮数。A：只按墙钟判（已实现，`hitStepBudget` 并列作参照）；B：照结果行字段判。
