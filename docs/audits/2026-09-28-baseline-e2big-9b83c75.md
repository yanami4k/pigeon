# 两类用例叠放运行参数过长（spawn E2BIG）修复审计

- 基线：formal-v2 的 9b83c75
- 分支：baseline-e2big
- 范围：`src/eval/stream-workspace.ts` 的 `StreamWorkspace.run`（工作区里跑一条带墙钟上限的命令）及其测试。跑用例的外壳 `STRANDS_PYTEST_SCRIPT`、`casesCommand` 与缓存身份摘要不变。

## 一、现象与复现

- 89 道题的两类用例预计算（`pigeon eval stream-baseline --check classes`，代码 dfb1804，镜像 pigeon-stream-strands:v6）中，题 36（步 110，提交 7b0f874c8e9abd1e6a845b32025b1936d7a3d4c8）之后一侧已落盘，之前一侧（叠放到 parent 187285680c0287ac30ec98bc630fef030c4a25b5）报 `spawn E2BIG`；其余 88 道算成。
- 复现：在服务器 pigeon-verify 上把基准目录复制一份，用未修改的 9b83c75 对同一清单、同一仓库、同一镜像续算（88 道读回，只算题 36），另以 `node --require` 挂一个只读的诊断预加载，在子进程参数总长超过 100 000 字节时打印参数条数与最长参数。结果与原运行一致（题 36 出错 `spawn E2BIG`），诊断记录：
  - 出错的是宿主启动 `docker`（`docker exec … /bin/sh -c <脚本>`），共 8 个参数，总长 137 916 字节；
  - 最长的是第 6 个参数，即 `sh -c` 的整段脚本，长 137 844 字节，超过 Linux 单个参数的上限 131 072 字节（MAX_ARG_STRLEN，32 页）；
  - 这段脚本以 `timeout -s KILL 1860 sh -c '<strands 用例外壳>' …` 开头，其中含 1174 个 `--deselect`。
- 同一环境的总参数上限（`getconf ARG_MAX`）宿主与 pigeon-stream-strands:v6 容器内均为 2 097 152 字节，未触及；触及的是单个参数的上限。

## 二、定位

- 叠放运行（`ReferenceCases.overlayAt`）经 `repeatRuns` 调 `strandsRuntime.runCases`，后者由 `runPytestResilient` 驱动：一次运行在写出 junit 报告前被杀时，从 `-v` 进度收回已完成的用例，把它们与卡住的那条逐条作为 `--deselect` 续跑。
- `runCases` 把测试文件与全部 `--deselect` 作为命令的词交给 `StreamWorkspace.run`；`run` 经 `timeoutWrapped` 把整条命令加引号拼成一段脚本，作为 `sh -c` 的一个参数下发。续跑时已完成的用例上千条，这一个参数即超过 128 KiB。
- 之后一侧用同一批测试文件跑成：两遍容器内存峰值约 760 MiB、没有卡住的用例，命令里没有成批的 `--deselect`。
- 题 36 进入续跑的起因：叠放运行里用例 `tests/strands/experimental/bidi/models/test_bedrock.py::test_receive_ends_when_stream_closed` 在 parent 的代码上空转不结束，两遍容器内存峰值 2041 MiB 与 1975 MiB（上限 2048 MiB），pytest 在写出报告前被杀，续跑时把已完成的用例全部排除。
- `applyHumanFiles`（逐个文件、内容经标准输入）、`pinTestConfig`（配置内容经标准输入）、参考工作区检出等叠放运行的其他子进程调用，参数长度与文件多少无关，不是出错处。

## 三、修法

- `StreamWorkspace.run`：拼成的脚本不超过 64 KiB 时照旧作为一个参数下发（行为逐字不变）；超过时改为下发固定的一小段 `eval "$(/bin/cat)"`，整段脚本经标准输入送入（`docker exec -i`），在容器里对同一段文本 eval。命令的每个词因此各自成为独立的参数原样到达，不再受单个参数 128 KiB 的限制，只受整条命令行的总上限（2 MiB）约束。
- `cat` 取系统目录下的绝对路径，不按镜像的 PATH 解析；超时仍由同一段文本里的 `timeout -s KILL` 执行；被执行命令的标准输入与原先一样为空（`cat` 已读到结尾）。
- 为何不改身份摘要：缓存身份为镜像与 `commandDigest(casesCommand)`，`casesCommand` 由 `STRANDS_PYTEST_SCRIPT` 的文本构成。本修法只改命令从宿主送进容器的方式，外壳脚本的文本与 pytest 收到的参数逐字不变，因此已算的 88 道缓存照常按身份读回、不重算。
- 余量：题 36 的 1174 条 `--deselect` 连同测试文件约 138 KB；strands 全部用例约六千余条，即便全部排除，总长也远低于 2 MiB。
- 同类的按批做法（`container-host.ts` 的 `RESTORE_BATCH`）不适用于这里：`--deselect` 必须出现在同一次 pytest 运行里，不能拆成多次运行。

## 四、测试与变异

- `stream-workspace.test.ts` 新增 1 个用例：经假 docker（`localDockerHost`，宿主真的启动子进程，走 `dockerStreamShell → containerExec` 的生产路径）跑一条带 1500 个 `--deselect` 的命令，节点号含方括号、空格、单引号与双引号；先断言拼成的脚本超过 128 KiB，再在镜像 PATH 与固定 PATH 两种方式下各跑一次，断言退出码为 0、未超时、参数个数一致、落盘的每个参数与给出的逐字相同；最后断言超长命令的墙钟上限照常生效（`timedOut` 为真）。
- 变异（服务器上）：把 `run` 里的判断改为恒走一次性传参（`viaStdin = false`），该用例精确变红，报错 `Error: spawn E2BIG`（`code: 'E2BIG'`），与现场报错相同；还原后文件 SHA-256 前 16 位与植入前一致（4f50b63724a83764），`git status` 无改动，该用例重新通过。
