## 二、接口不可猜的测试文件清单（316）

### 2.1 规则与实现

`eval/analysis/pigeon_analysis/unguessable.py`，命令 `python -m pigeon_analysis unguessable`，只读人的仓库、流清单与两类用例预计算结果（`<提交>.classes.json` 的 failToPass），不读任何运行结果。

- 对象：每题要做到的用例所在的测试文件，取该题提交里人写的最终版本。
- 导入：AST 遍历全文件，`import strands...`（含 as 别名）与 `from strands... import X`（含 as 别名、函数体内的导入）；相对导入与项目外的导入不计，星号导入只核对模块。
- 模块存在：起点提交的 strands-py/src 下有 `<路径>.py`、`<路径>/__init__.py`，或有以 `<路径>/` 开头的文件（命名空间包）。
- 名字有定义：起点提交该模块的模块作用域里绑定了它（顶层 def、class、赋值、带注解赋值、增量赋值、type 语句、import 与 from-import 的别名，含顶层 if、try、with、for、while 块里的），或它是该模块下的子模块。模块里有项目内星号导入的递归取那个模块的全部名字；有项目外星号导入或模块级 `__getattr__` 的，一律算有定义。
- 题面：照冻结代码 promptFor（test-files）重建——提交信息去掉末尾空白、应通过的测试文件名单、要做到的用例落在本题测试文件之外时的第二段名单。重建结果与冻结检出（f69af5d）的 `taskPromptOf`、`caseFile` 生成的 89 题题面逐字比对，89 题全部相同。
- 整词：前后都不是 ASCII 字母、数字或下划线。模块不存在时查第一个不存在的那一级模块名。
- 判定：文件里只要有一个"开工时不存在且题面未出现"的模块或名字，该文件记为接口不可猜，其中的要做到用例全部剔除。

已知局限：只按导入语句判，mock.patch 的字符串路径、getattr 与 importlib 动态导入不算；conftest 与夹具等测试辅助文件不查（判题时由人的版本放入）；语法错误解析不了的文件不判为不可猜、单列（本次为 0 个）；项目外星号导入与模块级 `__getattr__` 的模块按有定义算，只会少判。

## 四、分析脚本（analysis-rejudge）

- `reader.py`：`failed_case_lists` 读结果行的要做到失败用例列表与是否齐全；`rejudged_case_lists` 读重判结果，只取一致且齐全的行，不一致的另列。
- `interface.py`：逐行剔除清单里的用例（总数减剔除数、通过数减剔除用例中通过的条数）；剔除后无剩余用例的行记为要做到的为零（不进该分析，不需要剔除用例的结果）；剔除用例的结果优先取一致的重判结果，其次取结果行列表（齐全即可定；截断时编号不大于列表最后一条的可定），都定不了的行从该分析的表里去掉并列出；在调整后的表上调用与主判据相同的 analyze_primary（符号翻转检验、自助法区间、Holm 校正），不拟合混合模型。
- 一致性：两个效应的结论类别（测出变好、测出变差、未测出改善）与主判据相同即一致。报告在结论一节加一句，另设"敏感性分析：剔除接口不可猜的测试文件（决策 316）"一节：清单汇总、无剩余用例的题、逐用例结果的来源与行数、未采用的重判行、去掉的行、检验表、结论句与一致性句。
- 命令行：formal 加 `--unguessable` 与 `--case-results`；不给 `--unguessable` 时报告与原来相同。
