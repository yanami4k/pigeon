## S6 拒绝理由通道（决策 066）

- TUI 面板新增 [r] 拒绝并说明：按 [r] 打开理由行（提示落消息区），此期间按键交给输入区编辑，回车提交、理由逐字回模型，Esc 回到面板且不算拒绝（审批仍挂起）；双击 Ctrl+C 的退出布防在理由行期间照旧生效（退出键在按键路由最前）。
- 面板提示改为 `[y] 批准一次 / [n] 拒绝 / [r] 拒绝并说明 / [a] 本会话允许 / [d] 本会话允许(仅限当前调用所在目录)`；exec 档照旧不提供 [d]，同样提供 [r]。
- 决定记录新增可选的理由来源字段 `reasonSource`（人写 / 系统默认），加法式加入、不升 Event Log 版本（口径同 052），迁移完整性机检的拒绝决定夹具同步带上该字段。
- 标注口径：TUI [r] 与 CLI 输入了理由标人写；TUI [n]、CLI 留空标系统默认（治理层落默认文案「人工拒绝」）；deny 清单与无审批通道 fail-closed 的系统文案同样标系统默认。
- 既有断言「[n] 不带理由」原样保留；面板提示的逐字断言随新提示同步更新。

## S7 装配收拢（决策 067）

- 新增 application/launch-flags.ts：cli、tui 与 headless 共用一份模型与运行参数解析（含 `PIGEON_STREAM_FN` 回退与 `resolveStreamFnSpec` 的统一报错），导出三个入口共用的模型占位缺省常量（provider 与 model 均为 custom）。`--history-limit` 只在 TUI 侧启用，其余入口按未知参数响亮失败。
- 新增 application/session-runtime.ts：统一新建与 resume 的装配——作用域解析（worker 会话回到其工作树与委派策略）、固化 grant 种子物化、MCP 会话启动与启动提示回调、运行面构建；装配失败时先关闭已启动的 MCP server 再上抛。cli 的 REPL 与 resume、tui 的启动与 /resume 换绑都改为调用它，两处重复的 buildWithMcp 各自删除。
- 不给 cli 与 headless 装 worker 编排器（067 明确）。

## 行为变化

- 模型占位缺省统一：cli 由 custom/cli、tui 由 unknown/unknown、headless 由 custom/headless 统一为 custom/custom。该值进注入快照与 run.started 的 model 摘要，此前会把同一模型按入口分成三组；历史会话标签不做映射，旧记录保持原值。
- cli 补 `PIGEON_STREAM_FN` 回退：未给 `--stream-fn` 时改用该环境变量（此前只有 tui 读取，而 cli 的报错文案称支持），行为与既有文案一致。
- TUI 审批面板新增一个按键 [r] 与理由行输入模式；[n]、[y]、[a]、[d] 的单按语义不变。
- 决定记录多一个可选字段；不改变任何放行、拒绝或放权语义，也未新增审批通道。

## 已知边界

- 拆分后子模块通过 host 窄接口访问壳状态，壳因此多出若干公开方法（供子模块调用）；它们不是对外 API，测试与入口仍只用原有 6 个公开符号。
- 理由行复用输入区编辑：理由为空时回车不提交（留在理由行），与空输入静默忽略同口径。
- session-runtime 在 resume 路径上会再解析一次会话作用域（调用方为 resume 流程已解析过一次），属只读物化，未做缓存。
