# 冻结前加固：续跑时比对代码版本（决策 269、147）实现审计

- 基线：formal-v2 的 66d329c
- 分支：freeze-guard
- 范围：提交流跑批器的身份头与续跑（`src/eval/stream-identity.ts`、`stream-harness.ts`、`stream-experiment.ts`、`src/cli/index.ts` 里 `eval stream` 的参数），以及报告新增的设置一节（`stream-report.ts`，由 `stream-runner.ts` 转交身份头）。已有的身份比对（仓库、清单摘要、镜像、预算、条件、步的范围、题面、选题、试跑步数、两种 agent 的参数）不变。

## 一、比对规则

- 代码版本即身份头 `info.harness`：Pigeon 仓库 HEAD 的短提交号与是否有未提交改动（`currentHarnessRef`，读不到时提交号记 `unknown`）。此前只记不比，续跑时换了代码照样放行。
- "认得出"：提交号不是 `unknown`（也不为空）且没有未提交改动。
- 续跑（输出目录已有 `identity.json`）：先照旧逐项比对 core，不同即拒绝；core 一致后比对代码版本。记录的代码取 `infoLog` 最后一条的 `info.harness`，没有 `infoLog` 即取开跑时的 `info.harness`。记录的与当前的都认得出且提交号相同才算一致；否则拒绝续跑，身份头不动。由此以下情形都拒绝：提交号不同；当前有未提交改动；任一方为 `unknown`；记录的那份有未提交改动（认不出当时是哪份代码，同一提交的干净代码也不能认定相同）。
- 报错文案列出记录的与当前的代码，写法为"提交 <短号>（有/无未提交改动）"，并提示可用 `--accept-harness-change "<原因>"` 显式放行。
- 首次开跑（输出目录没有身份头）：当前代码认不出（有未提交改动或提交号为 `unknown`）即拒绝开跑，不写身份头，提示可用 `--allow-dirty-harness` 放行。
- 同一次跑批中身份头比对用的与结果行 `harness` 字段记的是同一次读取的代码版本（`runStreamExperiment` 只调用一次 `currentHarnessRef`）。

## 二、两个参数

- `--accept-harness-change "<原因>"`：只在续跑时起作用，放行上面任一种代码版本不一致。原因为空或只有空白即报错（命令行解析与 `checkOrWriteIdentity` 各查一次）。代码版本一致时给了这个参数不追加记录。它不放行 core 的不一致。
- `--allow-dirty-harness`：不带取值的开关，只在首次开跑时起作用，放行未提交改动或读不到的提交号（开发自测用）。续跑时它不放行代码版本不一致，续跑换代码一律要 `--accept-harness-change`。
- 两者经 `StreamExperimentOptions.harnessAllowance` 交给 `checkOrWriteIdentity` 的第四个参数（`HarnessAllowance`）。

## 三、留痕格式

- 显式放行代码更换：在身份头 `infoLog` 追加一条 `{ "since": <ISO 时刻>, "info": <当前的 info，含新的 harness>, "acceptHarnessChange": "<原因>" }`。之后续跑以这条的 `harness` 为记录的代码。同一次续跑若路数或账号也变了，并在这一条里，不另追加。
- 只改路数、账号数或各账号并发的记录格式不变（没有 `acceptHarnessChange` 字段）。
- 首次开跑经 `--allow-dirty-harness` 放行（当前代码确实认不出时）：身份头顶层写 `"allowDirtyHarness": true`；代码认得出时给了这个开关不写。
- 以上都不进身份摘要（`digest` 不变），与 `info` 同一口径；写入仍为先写临时文件再改名。

## 四、报告的设置一节

- `report.md` 标题之后新增"## 设置"一节，排在每步得分之前：
  - "开跑时的代码：提交 <短号>（有/无未提交改动）"；开跑经 `--allow-dirty-harness` 放行时括号内另写"经 --allow-dirty-harness 放行"。
  - `infoLog` 中每一条带 `acceptHarnessChange` 的记录列成一行表格：时刻、新的代码（提交号与是否有未提交改动）、原因；没有即写"显式放行的代码更换：无"。只改路数、账号的记录不列。原因里的竖线转义、换行换成空格。
- 身份头由 `runStreamExperiment` 在比对或写入之后读出（`readStoredIdentity`），经 `runStreams` 的新选项 `reportIdentity` 交给 `renderStreamReport`。没有身份头时不写这一节（直接调用 `runStreams` 的场合）。
- `describeHarness`（代码版本的写法）放在叶子模块 `stream-harness.ts`，报告只依赖它与结构类型 `ReportIdentity`，不依赖 `stream-identity.ts`：后者类型引用了 `stream-runner.ts`，报告若依赖它会与跑批器成环。

## 五、测试

- `stream-identity.test.ts`：新增 5 个用例——提交号不同即拒绝且报文列出两边的代码、身份头不动；当前有未提交改动、任一方为 `unknown`、记录的有未提交改动即拒绝；`--accept-harness-change` 放行并追加 `infoLog`（时刻、新代码、原因），之后以新版本为准、回到旧版本即拒绝，有未提交改动的同样可放行并留痕，代码没变时给了也不追加；原因为空或只有空白即报错、身份头不动；首次开跑有未提交改动或 `unknown` 即拒绝、不写身份头，`--allow-dirty-harness` 放行并写 `allowDirtyHarness`，干净代码给了也不写。原有两个用例里"换了代码照常续跑"与"只换代码不追加 infoLog"的断言改为同一代码版本续跑。
- `stream-report.test.ts`：新增 1 个用例——设置一节的开跑代码、放行表格各行、只改路数的记录不列、经 `--allow-dirty-harness` 放行的写法、无放行时写"无"、没有身份头不写这一节。
- `stream-runner.test.ts`：新增 1 个用例——输出目录的身份头经 `reportIdentity` 交给 `runStreams` 后，`report.md` 写出开跑代码与放行记录。
- 未覆盖：`runStreamExperiment` 里读出身份头交给 `runStreams` 的一行与命令行两个参数的解析，这两处要起镜像与网关才能走到，没有单测。
