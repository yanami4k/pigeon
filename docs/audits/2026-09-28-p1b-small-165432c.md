## 二、本地开启回炉不再要求 git 工作区（281）

### 2.1 改法

- src/application/headless-core.ts 的 `assertRepairSetup`：原先没有注入执行端（本地工作区）时，`isGitWorkspace` 为假即报"开启回炉却没有可用快照……目前只支持本地 git 工作区"，删去这一条。其余检查不变：回炉轮数须为非负整数；设了轮数须有验证命令；不得与失败自动分叉重试同开；容器执行端须提供记下这一步起点的能力；给了受保护文件须执行端能按起点还原。`isGitWorkspace` 的导入随之删去（该文件不再用它）。
- 快照挂载条件不变：没有执行端且（开了失败自动分叉重试、或是分支会话、或开了回炉）即调用 `attachCheckpoints`；它对非 git 工作区本就返回 undefined、不报错。因此：git 工作区开启回炉照旧在首次改动前记改前基线、改动后打快照；非 git 工作区开启回炉照常回炉、不打快照、不报错。
- /fork 在非 git 工作区的行为不变：src/application/fork.ts 的 `prepareFork` 仍以 `NotGitWorkspaceError` 报错、不降级（078），既有用例"非 git 工作区发起分叉：明确报错，不降级、不留分叉条目"照旧通过。
- 注释三处（回炉轮数选项、启动前检查、快照挂载）改为写明 281 的口径。
- 帮助文案与非历史文档里没有"回炉只支持 git 工作区"的表述，无需改。

### 2.2 测试（src/application/repair-loop.test.ts）

- 改写：原"启动即报错：开启回炉却没有可用快照（非 git 工作区）"改为"非 git 工作区开启回炉（决策 281）：不报错、照常跑完回炉循环，只是不打快照"。临时目录（先断言 `isGitWorkspace` 为假）里放 a.txt 与验证脚本 check.mjs，假模型四条回复（改成 half、收尾、改成 fixed、收尾），回炉轮数 3。断言：模型调用 4 次；回炉结果为一轮、通过、已收尾；标签 Passed；a.txt 为 fixed；两个 Run 的 Run 开始条目都冻结了回炉轮数 3；验证结论依次为 fail、pass；`storeRepairStepOutcome` 为一轮、通过；两个 Run 的快照条目数都为 0。
- 新增："git 工作区开启回炉：照旧在开工时打快照；/fork 回到回炉中间某一轮取到的是那一轮开工前的工作区"。真实 git 仓库，同样四条回复。断言：两个 Run 各有 1 个快照；首个快照带改前基线，基线里 a.txt 为 bug，首个快照为 half，第二个快照为 fixed，第二个快照不带改前基线；`prepareFork` 到第二个 Run 第 1 条（回炉反馈）取到首个快照的提交，分支工作树里 a.txt 为 half，且按已有消息续跑；`prepareFork` 到首个 Run 第 1 条取到改前基线，分支工作树里 a.txt 为 bug；用户工作区的 a.txt 仍为 fixed。
