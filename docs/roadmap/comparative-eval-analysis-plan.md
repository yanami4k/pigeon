# 对比评测分析计划（预注册）

本文写定对比评测的主判据算法、检验方法、报告措辞与试跑的取值规则，于试跑开始之前入库。入库之后的改动只能在文末以带日期的修订行追加，且须在看到正式结果之前；报告引用本文入库时的提交号。

立场：研究型项目，负结果照实报告；小样本不下变好变差的结论；差距在本设计分辨不了的范围内时如实写，不找有利的解释。

## 0 实验设置

- **问题**（385）：完整产品的 Pigeon 与对照 harness，原样拿来用，在同一组题上谁做得更好。只比整体，不拆机制。
- **仓库与题目**（388）：strands 的 89 道题去掉上一轮九次运行全满分的 10 道（第 17、18、54、60、76、128、140、165、178、181 步），留 79 道，按时间接成一条流。不按其他旧结果剔题，不设用例数下限。
- **起点**（389）：每一步从人在该步之前的代码开工（固定起点）。两组各带自己产品自带的跨题能力：Pigeon 会话检索开，同一作业内后面的题能检索前面题的会话；对照 harness 无人值守模式没有跨会话能力，原样不带。
- **两组**：
  - P：Pigeon 打包产物在题目容器里以产品缺省跑 `pigeon run --yolo --no-web --json --thinking high`（派 worker、会话检索、裁剪、压缩、截断续跑等都按产品缺省）；设置与程序状态锚在题目仓库之外的治理目录（题目仓库自带的 .pigeon/ 不生效）。
  - D：对照 harness 的无人值守模式在题目容器里以其缺省跑，版本锁定，权限全放行，每题独立的家目录。
  - 两组共用：同一套题面（提交信息、应通过的测试名单与接口说明，前接同一句工作方式指令），同一个模型网关、同一模型（deepseek-flash）、都开思考档位 high（390、397；温度不下发），联网工具都关，容器只通网关，判题同一套。
- **遍数**（391）：两组各两遍。一遍为一个作业（组 × 遍），作业之间会话互不相通；四个作业在同一台服务器上并行。
- **跑批设置**：高峰自动暂停开（393、395，余量 30 分钟），网关逐请求留存开（394）。每步上限见第 5.3 节（398）。
- **版本**：试跑结束、开正式跑之前把实验代码打标签冻结，身份头记 Pigeon 产物摘要与对照 harness 版本；续跑时版本不符即拒绝。
- 记号：题 i = 1…n 按时间顺序；遍 r = 1、2；y(g, i, r) 为组 g 在第 r 遍第 i 题的部分得分，取值 0 到 1，报告时换成百分点。

## 1 每一步的计量

与上一轮正式跑相同（214、201）：

- **两类用例**：人在该步的测试放到人该步之前、之后的代码上各跑两遍。之前没过、之后两遍都过的为"要做到的"（F）；前后四遍都过的为"不许挂的"（P 类）；任一侧两遍结果不同的排除、单独计数。
- **部分得分**：y = F 中在 agent 代码上通过的条数 ÷ F 的条数。
- **F 为空的步**：照常跑，不进主判据分母；报告单列。
- **作废重做**：基础设施或模型服务故障按跑批器规则作废重做，以重做结果为准；重做到上限仍失败的记为缺失。

## 2 主判据

### 2.1 两组之差

先把两遍合起来：ȳ(g, i) = 该组在第 i 题上已有效各遍的平均，各遍等权。对每道有效题 i：d(i) = ȳ(P, i) − ȳ(D, i)。效应估计 Δ = d(i) 在全部有效题上的平均，每道题等权。只有这一个主判据（401）；做成与否作次要判据。

### 2.2 有效题与缺失

- 有效题：F 不为空，且两组在该题上各至少有一遍有效结果；某组某遍缺失的按该组另一遍计。
- 任一组在该题一遍有效结果都没有的，该题不进主判据，报告列出题号与原因。
- 缺失题超过有效题的 10% 时，报告置顶注明，结论降格为"探索性"。

### 2.3 检验

- **主检验**：按题配对的符号翻转置换检验，随机翻转 100,000 次，p = （翻转后平均差的绝对值不小于实测的次数 + 1）÷（翻转次数 + 1）。双侧，显著性水平 5%（只有一个主判据，不做多重校正）。
- **置信区间**：按题自助法，题目有放回重抽 10,000 次，取 2.5% 与 97.5% 分位数。
- **稳健性对照**：线性混合模型 y ~ 组 + (1｜题) + (1｜作业)。与主检验方向或显著性不一致时，报告写明"结论对建模方式敏感"；不收敛时注明，主结论照主检验。
- **效应量**：主报 Δ 的百分点数与置信区间；附 dz = mean(d) ÷ sd(d)；另报相对差 = Δ ÷ ȳ(D) 的平均。
- 置换与自助法的随机种子事先写定，附在分析代码里。

### 2.4 设计灵敏度

报告写明本设计能以 80% 把握分辨的最小差距 M：用本次数据，M = 2.80 × sd(d) ÷ √n（2.80 = 1.96 + 0.84）。开跑前按上一轮同格两遍的出入推算，79 道题、两遍约 6 个百分点（391）。

## 3 次要判据与解读顺序

次要判据只作佐证，一律标"探索性"，p 值不做校正。

| 次要判据 | 算法 |
|---|---|
| 做成与否 | 做成 = F 全部通过且 P 类无一失败；两组做成率之差按 2.1 的配对方法算，给置信区间 |
| 不许挂一类的失败 | 每步 P 类中失败的条数；报两组合计、每步平均、有失败的步数，配对差同上 |
| 随题目推进的变化 | d(i) 对题的时间位置 t(i)（第 1 题记 0、最后一题记 1）做最小二乘回归的斜率；后半段差 = 后一半有效题 d 的平均 − 前一半的平均（奇数时去掉正中一题）。Pigeon 的会话检索随题积累，斜率为正与之相符，但只作描述 |
| 花费与效率 | 每步网关花费（按非高峰价折算）、输入 token（命中与未命中）、输出 token（含思考）、墙钟、请求数；报两组中位数与 90 分位，按题配对取差的中位数 |
| 撞上限与作废 | 每组撞每步上限的步数、作废重做次数、最终缺失数 |
| Pigeon 的机制使用 | 每步会话检索调用次数与命中会话数、派出的 worker 数与角色、裁剪与压缩次数、截断续跑次数——只描述，不作因果解释 |

解读顺序：先看主判据；显著时再看做成与否与不许挂一类，核对"部分做对"有没有变成"整体可用"、有没有以弄坏旧功能为代价；花费与效率单独报告，不用来改写主结论；主判据不显著时，次要判据只报方向与区间。

## 4 报告的固定措辞

- **显著且 P 更好**："在 n 道题、两遍下，Pigeon 每步要做到的用例通过比例比对照 harness 平均高 X 个百分点（95% 置信区间 [a, b]；按题配对的符号翻转检验，p = …）。"
- **显著且 D 更好**："……平均低 X 个百分点（……）。"照实写。
- **不显著、区间落在 ±M 以内**："在 n 道题、两遍下，两组相当：估计差 X 个百分点（95% 置信区间 [a, b]，落在本设计能分辨的最小差距 ±M 以内）。"
- **不显著、区间超出 ±M**："在 n 道题、两遍下，未测出两组的差别：估计差 X 个百分点（95% 置信区间 [a, b]）；不能排除约 M 个百分点以上的差距。"不写"没用""证伪"。
- **两组都接近满分**：两组平均部分得分都 ≥ 90% 时，结论后加"（两组都接近满分）"。
- **结论对建模敏感**：照 2.3。
- 花费结论单独一句，不与得分合并成"性价比"。

## 5 试跑与取值规则

### 5.1 试跑设置

- 两组各一遍；题目：从 79 道里 F 不为空的题中以 Python 的 random.Random(20261007).sample 抽 8 道，按时间排序；Pigeon 的会话在这 8 道之间照常保留（400）。
- 试跑结果不进正式结论。以下规则只看花费、上限、机制是否正常，不看两组得分之差。

### 5.2 花费与预算

- 计量：网关按官方现价逐请求计的花费，分组、分步记；高峰时段的按非高峰价折回。
- 推算：正式跑 C = 79 × (cP + cD) × 2 遍 × 1.2，cP、cD 为试跑两组的每步平均花费，1.2 为后段题更长与作废重做的余量。
- 按 C 充值后开跑。正式跑不设会半路停批的总花费上限（上一轮因上限半路停批浪费在途步，见 318–321）；只保留每步上限防失控。
- 账单核对：试跑后以 DeepSeek 控制台账单核对一次网关计费，差异超过 5% 先查明再开正式跑。

### 5.3 每步上限

- 两组同一墙钟上限，轮数各按自己产品的缺省（两边都不限轮数）（398）。试跑取每步墙钟 60 分钟，结果行记每步是否撞上限。
- 试跑有任何一步撞上限：先看轨迹判断是在打转还是题确实做不完；打转先在产品里解决，不靠放宽上限掩盖；题确实做不完则正式跑上调到 120 分钟并在报告里注明。只上调不下调。

### 5.4 机制核对（不通过即先修再开正式跑）

- 网关留存里 DeepSeek 回复的思考块签名非空、多轮请求没有 400（396）。
- 两组每步都有网关留存，留存里没有鉴权头与 key；每题留存体积与估算（0.8–1.6 MiB）相符或说明原因。
- 容器里 Pigeon 派 worker 正常（若试跑中模型派了）。
- 工作树占盘（399）：工作树照产品原样不自动删。试跑测出每题派出建工作树的 worker 平均数 k；推算占用 k × 33 MB × 79 × 2 × 1.5 超过服务器剩余空间减 5 GB 时，正式跑前改为跑批器判完一题即删该题的工作树，并在报告里注明。
- 高峰暂停在跨进高峰时按预期停放与恢复（试跑若不跨高峰，注明未覆盖）。
