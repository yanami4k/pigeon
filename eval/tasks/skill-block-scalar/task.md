# Skill 前言解析支持 YAML 块标量

`src/skills/catalog.ts` 的 `parseSkillFrontMatter(text: string): { name?: string; description?: string }` 解析 `SKILL.md` 开头 `---` 围起的前言块，目前只认单行的 `name:` 与 `description:`（引号可选）。很多 Skill 的简介较长，习惯写成 YAML 块标量，例如：

```yaml
---
name: deploy
description: >
  部署前先跑
  全量验证
---
```

现在这种写法会把 `description` 解析成字面量 `">"`。请让解析器支持块标量。

## 期望行为

对任一被识别的键（`name` 或 `description`），若冒号后的值去掉首尾空白后恰为 `|`、`|-`、`|+`、`>`、`>-`、`>+` 之一，则按块标量处理：

1. **块的范围**：从下一行起，连续收集"空白行"或"以空格或制表符开头的行"，遇到第一个非空白且不缩进的行（例如下一个键）或前言块结束时停止。块内的行不再作为键值行解析。
2. **去公共缩进**：取块内所有非空白行前导空白长度的最小值，每个非空白行去掉这么多前导字符；空白行视为空串。
3. **拼接**：
   - `|`（字面块）：各行用 `\n` 连接，保留去公共缩进后多出来的缩进；
   - `>`（折叠块）：相邻非空行用一个空格连接；每个空白行产生一个 `\n`，且空白行之后的下一行前面不再加空格。例如行序列 `a`、`b`、空行、`c` 折叠为 `"a b\nc"`。本任务不要求处理折叠块中更深缩进行的特殊语义。
4. **收尾**：结果去掉首尾空白。`-` / `+` 保留指示符只需被接受，不影响结果（结果永远不带尾部换行）。结果为空串时视为该键未提供（返回对象里没有这个键）。
5. 前言使用 CRLF 行尾时行为相同。

其他行为保持不变：单行值与引号剥除、未识别的键被忽略、无前言返回 `{}`、其他键（如 `metadata: |`）后面的缩进行不会被当成 `name` 或 `description`。

## 约束

- 只改 `src/skills/catalog.ts`，函数签名不变。
- 可以用 `node --test <测试文件>` 自测。
